# FX 50 人实机压测结果

目标：https://thccb.secret-sealing.club。轮次：`fx50_20261017_live`。

**结论：50 人正常交易短时可完成目标吞吐，没有出现百人测试的大量超时；成交尾部延迟触发保护，五分钟稳态尚未完成。**

停止原因：滚动 30 秒的成功成交 P99 超过预设 2 秒。

正常阶段运行 44.06 秒（包含停发后的排空），56 次成交请求全部成功，439 个 HTTP 请求全部成功。成交 P50 为 **283.963ms**，P95 为 **1762.522ms**，P99/最大值为 **2259.433ms**。全轮 1894 个采样结果均成功，没有观测到 429、5xx 或网络/请求超时。

只读阶段结束时 50 条公开 SSE、50 条私人 SSE 全部在线。正常阶段结束统计的 0/0 包含客户端主动停测退出，不能理解为全部 SSE 自然断开。全轮未采样到 SSE 错误。

本轮未修改业务代码、连接池、Nginx 或保护阈值。准备脚本仍创建 100 个可用测试账户，**只有其中 50 个登录并产生负载**；其余 50 个未连接、未操作，清理时一并删除。在线角色 30 现金、10 融资、10 空头，持仓准备与初始页面读取单列。各轮市场克隆的是准备当时原市场的储备，不能视为池子初始状态完全相同的严格对照实验。

## 与百人结果对比

| 正常交易阶段 | 50 人 / 100 SSE | 100 人 / 200 SSE |
| --- | ---: | ---: |
| 目标成交尝试/s | 1.25 | 2.5 |
| 实际成功成交/s（含排空时长） | 1.271 | 0.190 |

| 成功 HTTP / 完成 HTTP | 439 / 439 | 90 / 274 |
| HTTP 超时 | 0 | 184 |
| 成功成交 P99 | 2.259 秒 | 4.422 秒 |
| 保护停止原因 | 成交 P99 > 2 秒 | 超时等错误率 > 5% |
| 清理前连接池错误摘要 | 未发现 | 明确出现 size10 + overflow20 耗尽 |

这说明本轮 50 人没有出现百人时的池耗尽故障，能够短时完成约 1.27 笔/s；成交尾部仍慢。56 个成交样本较少，P99 在此采用最大观测值；不能据此证明 50 人五分钟乃至长期稳定，也不能推出 SSE 的硬上限就是 50 或 100。人数减少同时减少版本查询与交易量，本轮没有分离这些因素。

## 资源和诊断证据

[服务器资源采样](server-final/server-metrics.jsonl) 共 30 组，窗口 09:36:49–09:41:44 UTC，覆盖入场、角色准备和大部分只读；**未覆盖随后正常交易的高延迟窗口**，不能把以下数字称为正常交易阶段的资源峰值：

- 后端 Docker CPU 采样峰值 69.76%，末次内存 128.6MiB。
- PostgreSQL Docker CPU 采样峰值 19.97%，末次内存 155.1MiB。
- 数据库连接采样峰值 10，活跃峰值 2，锁等待峰值 0。

Docker CPU 100% 表示一个 CPU 核的用量，采样间隔可能漏掉短峰值。清理前另读取近 15 分钟错误摘要，覆盖正常交易窗口：[backend-errors.json](server-final/backend-errors.json) 的 pool_errors 为空、TimeoutError 和 deadlock 文字计数均为 0。该证据只能说明未捕获到这些错误，不能证明完全没有连接等待。
