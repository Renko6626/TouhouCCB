# 4Hz与双层ASGI在50次流程每秒下的短测

结论：当前单owner在本轮合成整页负载下明显过载，不宜承诺持续50次交易流程/秒。目标50，测量窗口内成功POST22.00次/秒；不能将这一个过载点当作已找到精确最大容量。

| 指标 | 结果 |
| --- | ---: |
| 用户 / SSE | 100 / 200 |
| 测量窗口 | 40秒，另10秒预热与排空 |
| 计划流程 | 2000 |
| 窗口内成功POST | 880（22.00/s） |
| 最终成功流程，含排空 | 942 |
| 忙用户跳过 | 1017 |
| 报价version_conflict | 41 |
| POST P50 / P95 / P99 | 2697 / 4228 / 4459ms |
| 完整流程P99 | 5910ms |
| owner CPU | 96.6%单核 |
| 采样writer队列峰值 | 96 |
| 客户端CPU / 到达迟滞P99 | 52.9% / 410ms |

1017次跳过表示该用户前一流程尚未完成，压测器没有再次发起这次计划；已提交的942笔POST全部成功。41次报价拒绝均为version_conflict。不能只看POST无HTTP错误就判定达到50/s目标。

CPU/SQL/队列以1秒采样，capacity标记包含部分排空时间（约43.1秒资源采样），不是严格40秒积分；客户端到达P99迟滞约410ms，施压也有明显抖动。单轮共享开发机结果用于识别过载，不能宣称精确容量上限。

当前代码cf62986，4Hz＋双层纯ASGI。复用上轮同一driver，仅把CLI允许的rate列表补入50，其他负载流程不变；源文件摘要见environment.json。保留真实风控日志、三个客户端连接池、60%现货/20%融资/20%做空、一热点币种、HTTP报价、交易后刷新和版本轮询。普通前端主要使用本地报价，因此该合成负载较实际普通页面更重；纯下单接口容量未测。

独立本机PostgreSQL，Unix socket，fsync与synchronous_commit开启，新建fxcapacity_asgi50_test库，未访问生产。结束时100公共+100私人连接；资金/国库/利息调整差额为零，成交腿与持久事件数一致。首公共观察者已确认交易事件缺失为零，不证明所有客户端或私人通知逐条必达。
