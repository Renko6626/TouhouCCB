# Task 4 snapshot/risk preflight

Read-only code investigation against approved plan §§2.2/2.3, including its added same-account concurrency requirement. No implementation, commits, tests, services, or extra agents. This report is the only file written. Concurrent FX/LMSR implementation was not reviewed; writer installation details below were read from committed HEAD where relevant.

## Main finding

`credit/risk.py` does **not** consume `PricingRegistry` records. Its actual liquidation inputs still come from SQL. `_writer_state()` contributes LMSR mirror q/status only to the cache/version tuple, while `_quote_group_value()` uses SQL outcome q/status/b. Removing GATEs, improving SQL statement cohesion, or changing ordinary read behavior cannot by themselves implement the approved execution-time published-market semantics.

The local `6526700` commit contains no `risk.py` change (`git show --stat`); treat it solely as a reference for ordinary reads. In particular, do not assume it supplies the missing risk input conversion.

## Which fields are missing from published records?

| Needed input | Current record | Required treatment |
|---|---|---|
| FX reserves, buy and sell fees, pool version, status, reduce_only | All present in `FxReadState` (`market_read_state.py:11`) | Build **both** `FxPairSnapshot` and `FxShortPairSnapshot` from the same captured record; no SQL pair metadata override. |
| LMSR b, ordered outcome IDs and Decimal q, status, closes_at | All present in `LmsrReadState` (`market_read_state.py:34`) | Build every `OutcomeSnapshot` from this record, matching IDs with q; stop reading SQL q/status/b and stop consulting mutable writer state for foreign-market valuation. b is already a float in the model and record; this is not a new precision change. |
| LMSR sell fee | Absent from `LmsrReadState` and its pricing hash | This is an existing **global rule**, not a per-market field. Minimal scope: retain the authoritative locked-execution `SiteConfig` fee read (`_current_rates`), explicitly separate from market records. `site_config.py:163` already rejects runtime changes to loan rate/sell fee during unified credit operation. No need to expand every market record merely to duplicate this rule. Include the effective fee in risk cache versions. |
| User cash, gold debt/accrual timestamp, economic_version, freeze | Deliberately absent | Re-read from the locked User, never infer from prices. `_refresh_user_authority` refreshes ORM data but does **not** acquire the lock. |
| User Position/FxWallet amounts and full dependency set | Deliberately absent | Query all relevant account rows after acquiring User lock. Market/outcome IDs needed to identify holdings may still come from SQL; valuation q/state must come from the captured records. |
| User FxShortPosition principal/interest/accrual timestamp | Deliberately absent | Query all this user's live obligations after User lock; attach them to captured FX market inputs. Never use an old record or an old discovery snapshot as a substitute for this ledger. |
| Pair/global aggregate short debt; short lending limit | Absent from `FxReadState` | Neither is an input to the existing `credit/risk.py` A/K/E/B quote: `_short_risk_after` sums **this user's** per-pair debt, and `quote_fx_short_group` needs this user's effective debt plus FX quote inputs. Do not invent a market aggregate or add it to records. Any existing target-market lending/capacity accounting belongs to its existing target transaction, as the approved plan requires. |

Thus there is no missing published LMSR outcome q/status and no missing FX quote fee. The missing link is consumption of existing records, plus deliberate separation of account debt and global rules.

## Where stale account discovery survives the User lock

1. `discover_dependencies` (`risk.py:686`) is explicitly a lock-outside API. It reads User, positive positions, positive wallets, live shorts, rules, and SQL market metadata. It does not acquire User or market locks.
2. `check_new_risk` (`1348`) and `check_cash_spend` (`1545`) refresh User, but `_revalidate_post`/`_revalidate_cash` (`1097`/`1124`) rediscover account amounts **only if** economic_version differs. The existing User lock therefore does not itself ensure every holding/debt/dependency used by a check was read after that lock. Minimal-deps callers are another concrete example (`test_credit_short_risk.py:174`).
3. `_persisted_short_pair_ids` (`1207`) checks only IDs. Newly seen obligations are rejected as `version_conflict` before they can be priced, because the old design cannot add GATEs under User lock. Same-ID debt refresh is restricted by `_short_refresh_ids`, and all market refreshes still use SQL. This is not the new requirement to read the full fresh account and price its dependencies while retaining User lock.
4. `gated_groups` comparisons in both checks reject newly discovered position/wallet/short groups. These checks must disappear with the freeze-dependency model, not be retained under a new name. A fresh own holding can be valued immediately from its already published market record without any writer or collateral lock.
5. `_refresh_group_snapshots`, `_guard_and_refresh_prices`, and `_refresh_collateral_snapshots` only refresh quotes/selected short rows; they do not refresh full holdings. Their `merged.update(fresh)` pattern also retains old entries when a needed source is absent. A missing/unhealthy published record must not silently retain discovery's old market input.
6. `_rebase_post` (`941`) rebases cash/debt/long holdings but not absolute `post.short_debt`. Moving all refreshes into one generic check without preserving target simulation semantics can therefore reuse an old absolute short debt. Build target simulation from the locked fresh account, or retain a proper stale-target rejection until the caller rebuilds it.

Example external caller retained in scope: `_borrow_unified` (`api/v1/loan.py:82`) discovers before GATE/User lock and explicitly retries on version changes. Replacing only the inner pricing helper leaves this obsolete outer dependency-freeze lifecycle in place.

## Narrow patch recommendation

1. Add a **synchronous, no-I/O** registry accessor that returns available immutable committed `PricingRecord` references for requested keys, for the active owner/writes-enabled lifecycle. Risk must not call current `_read_records`, `read_groups_locked`, or `read_fx`: these can GATE-wait, cold-load, or publish. Health/lifecycle decisions must follow the approved active/unavailable/deleted distinction. Missing active owner state denies the economic operation and lets its existing writer recovery run; no SQL fallback or install from the risk path.
2. In each affected execution handler, preserve target market → User lock order and perform final account discovery **after** User lock and **before** constructing the final financial simulation or changing funds. Read fresh cash, gold debt, all wallet/position/short amounts, freeze/version, full dependency IDs, and execution rules. This is account bookkeeping, with no foreign-market `FOR UPDATE`/`FOR SHARE`, GATE, or writer query. Keep User lock through commit/rollback. Risk does not acquire a target lock or wait for another actor.
3. Once account IDs and target post-state requirements are known, capture the needed registry records once, without await between captures. Convert that fixed set to GroupSnapshots; reuse it throughout A and K, including later missing-snapshot handling. Do not call a second registry refresh or SQL supplement from `_ensure_snapshots` during the same check. Foreign markets may have different observed times. Later market publications do not invalidate this check or cause retry.
4. Keep the actual target execution state authoritative: target handler supplies current real reserves/q and fee/status simulation, guarded against its own stale simulation. Do not demand a new target registry record between DB commit and install: the approved window allows the previous committed market record. In particular, the just-refreshed **own** debt/holding ledger must override any older account-related data or retained discovery data. Reuse existing `PostTradeState` override design rather than add a queue or ledger snapshot mechanism.
5. Replace the SQL quote-building path in `_load_snapshots`/`_load_short_snapshots` for execution risk. Split own-short ledger reads from FX pair metadata; both FX asset and cover snapshots must use one captured record. Remove mutable `_writer_state` from foreign input/version construction. Cache key still includes fresh account economic_version, captured market inputs/stamp, and effective fee; do not mix SQL q with a published version.
6. Remove old ungated-new-dependency/short-ID rejection and collateral-market-change retry conditions after the locked full-account path is wired. Preserve true target simulation/version failures, unavailable-market failures, invalid-debt/unknown-K failures, ownership checks, and fund/ledger invariants. Avoid keeping old snapshots via map merge when a required record is unavailable.

Important caller hazard: standalone borrowing currently normalizes `debt_last_accrued_at=now` because its `post.debt` already includes pending interest. An unconditional fresh-deps replacement inside `check_new_risk` can restore the old accrual timestamp and charge the same pending interest twice. Refresh the final account before constructing this normalized post, or preserve the normalization intentionally. The same caution applies to rebasing an absolute target short debt. These are reasons to wire the final locked refresh at handler preparation, rather than simply swap `_load_snapshots` and leave all discovery order unchanged.

No new tables, account queue, recovery state machine, collateral row locks, or cross-writer requests are required.
