- 对上述已再次升级的临时库执行 `pg_dump -Fc`，在新建的 `touhouccb_fxshort_restore_test` 中 `pg_restore --no-owner` 成功；恢复后的 revision、旧现金／金债／钱包／现货 purpose 与源库一致。该合成备份没有活跃短债，不等同于生产规模或生产备份恢复演练。

### 无新增信用的现货交易性能门

在同一台本地 PG 14 上，对空头前提交 `931cd76` 和当前分支使用相同的合成种子、相同测试脚本、独立空库：四个并发 worker，每轮 100 笔无债无空头的 FX buy，三轮均无拒单。临时探针已删除，原始输出保留在本机 `/tmp/fxshort-perf-base-repeat.log` 与 `/tmp/fxshort-perf-head-combined.log`。当前版已把 User 锁后的空头欠币／锁金读取与幂等查重合并为同一 SQL，现金不变量仍保留。

| 版本 | 三轮 P95 ms | 三轮 P99 ms | 三轮成功吞吐 ops/s |
| --- | --- | --- | --- |
| 空头前 `931cd76` | 125.602 / 120.440 / 124.852 | 151.187 / 123.138 / 127.803 | 42.31 / 38.38 / 38.41 |
| 当前合并读取版 | 136.943 / 140.295 / 133.045 | 144.935 / 144.711 / 136.653 | 35.42 / 34.18 / 35.38 |

以三轮中位数计，当前版本吞吐约低 `7.9%`，P95 约高 `9.7%`，P99 约高 `13.2%`；相邻样本有明显波动。这**未证明**达到计划约 5% 的相对回归目标。额外的 User 锁后外币义务／锁金查询是维护同一现金与授信不变量的必要检查，不能为了数字删掉。开空上线前应在代表性数据和隔离负载下复测，并决定是否需要安全的查询／数据模型优化；不以这组临时 PG 数字作为生产 SLO。

## 发布操作顺序（尚未执行）

1. 在维护窗口确定旧金债与外币利率、配置快照和审计截止 ID；对数据库做完整一致备份（例如 `pg_dump -Fc -f <backup-file> <database>`），并验证备份可在隔离环境恢复。检查旧 `fx_wallet` 无负数，记录各 pair 储备、treasury 与用户现金／金债。保持 `fx_short_enabled=false`，所有 pair 借出额度为零。
2. 停止全部经济写入口和调度器：API 写实例、market writer、FX tick、金债结息和强平扫描；确认没有仍持有写所有权的旧进程或在途交易。若需改 `loan_daily_rate`，先在停写条件下运行 `python scripts/change_loan_daily_rate.py --rate <new-rate> --operator-user-id <admin-id>`，由同一事务按旧率结清金债与外币利息后切率；不能直接改配置。本次没有实际执行该维护命令。
3. 在备份与停写确认后，用目标库的 `DATABASE_URL` 执行 `alembic upgrade fx_short_debt_20260930`；检查 Alembic 版本、旧数据保留、新表约束、旧成交 `purpose=spot`、额度默认零。若迁移失败，保持停写并从已验证备份恢复，不跳过失败约束继续启动。
4. 同步部署识别外币欠币、锁金和可空风险值的所有读写实例；启动能力门必须在存在外币欠币时拒绝 `unified_credit_enabled=false`。先保持开空关闭，运行 `python scripts/audit_verify.py`、旧现货／借还／消费／强平回归，核对钱币库存、用户账、审计和活跃 run；开空闸关闭仍须允许存量空头回补和强平。
5. 只有 PG 并发、审计、迁移、性能门和运维回退检查全部验收后，运营再显式设置少数 pair 的非零额度，按小流量逐步开启 `fx_short_enabled` 并观察拒单、门闩等待、扫描时长、坏账／blocked run 和审计对账。该步骤不是本次代码验收的一部分。

## 回退边界（尚未执行）

先关闭新开空闸并把新借出额度设零，保持新版回补、估值与强平处理存量义务。旧镜像不能识别外币欠币和锁金；切回旧写实例前，必须在停写条件下确认 `fx_short_position` 的本金、利息、锁金均为零，未知风险快照与 `cover_group` 历史已按迁移保护条件处理并备份，再执行有条件的 `alembic downgrade -1` 和旧镜像切换。若不能清仓，只能继续运行支持空头的新版，或按单独审批恢复与旧镜像匹配的完整旧备份；不能把欠币按固定汇率折算成金债，也不能靠旧实例不认识的 flag 保护数据。
