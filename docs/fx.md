# FX 恒定乘积 AMM 运维说明

FX 使用金圆券与外币的恒定乘积 AMM。央行目标价、随机游走、噪声订单、新闻冲击和 FX 新闻模块已移除；没有真实成交或人工流动性调整时，池价不会自行变化。

本次发布采用[用户资料迁移与数据库重建](fx-database-rebuild.md)，旧市场、持仓、债务、成交和新闻不导入新开局。用户登录身份、权限和选定资料保留，现金按明确的新开局金额重置。本次代码交付本身不执行生产迁移或开市。

## 代码与存储

| 职责 | 入口 |
| --- | --- |
| AMM 数学和金额精度 | `backend/app/services/fx/amm.py`、`quantize.py` |
| 现货成交、开空和回补 | `fx/trading.py`、`fx/shorts.py` |
| 注资与撤资 | `fx/liquidity.py` |
| 行情增量、缓存、K 线落库 | `fx/market_state.py`、`market_reads.py`、`candles.py`、`candle_flusher.py` |
| 账户估值与强平 | `backend/app/services/credit/` |
| 管理接口 | `backend/app/api/v1/admin_fx.py` |

`fx_pair` 保存池子储备、费率、开盘元数据和状态；`fx_treasury` 是系统借币库存和手续费账户；`fx_wallet` 保存现货；`fx_short_position` 保存外币欠款和锁定所得；`fx_trade` 保存真实成交。`fx_event` 表及目标价、干预日预算列已删除。

## 开市与注资

新库导入后先保持交易、贷款和自动执行相关开关关闭。管理员通过现有后台创建市场并检查账户、库存和费率，再按活动方案开放交易。

- 创建输入保留币种代码、名称、初始储备、开盘元数据、手续费和借币上限。前端通过开盘汇率及池子规模换算储备，实际价格以量化后的储备比值为准。
- 手续费范围 `0 <= rate < 1`，金额最多 6 位小数，池子两侧储备必须为正。`initial_price` 不构成未来价格上下界。
- 管理端最多同时开放 3 个交易对；开市后币种代码不可更改，名称可修正。
- 注撤资只走 `POST /api/v1/admin/fx/pairs/{id}/fund` 和 `/withdraw`，请求为 `gold_amount/foreign_amount`。禁止手改储备绕过锁、版本和审计。
- 现有发行规则保持：创建／注资分别向池子和 treasury 增加相应数量，两者余额分别展示。借币库存不是池子储备的另一种显示，不能混算。
- `fx_enabled` 与 `fx_short_enabled` 继续控制普通成交和新增空头。币种的 `short_lending_limit_foreign`、可借库存和账户风控共同约束开空。

七项旧干预配置已删除：`fx_hourly_sigma`、`fx_step_max_ratio`、`fx_noise_interval_sec`、`fx_noise_pool_ratio`、`fx_system_half_life_sec`、`fx_default_price_move_limit`、`fx_daily_budget`。新闻和事件 API 已移除，不再有定时事件或干预后台任务。

## 借贷和强平

保留真实借款／借币及全仓信贷内核：做空借出 treasury 外币并卖入同一 AMM，所得计入现金但锁定用于回补；回补买足欠币归还。锁定所得不能重复当作可用现金。每次真实成交在数据库事务内重新报价，保留滑点限制、幂等键、行锁和提交后通知。

统一信贷启用时，FX 与预测市场共享权益；展示采用边际价，风控采用实际可清算价值。传统模式和统一模式的准入差异沿用既有规则，详见[统一信贷说明](unified-credit-risk-2026-10.md)。

强平仍由定时扫描发现候选，分页批量估值、限并发执行、锁内重新检查。一次价格更新不会触发全量强平。扫描间隔及部分清算比例本次不调参；后续性能优化另行评估，不能把本次删引擎理解为已实现新的风险缓存或清算队列。

暂停和 reduce_only 继续使用既有状态语义。归档／删除仍检查用户持仓和外币义务；有交易历史的市场使用归档。已经移除的新闻表不参与市场清理判断。

## 行情和历史

复用 main 的增量行情实现：提交后的真实成交按 pair 游标消费，维护内存 ring；每 5 秒批量写入 K 线和持久游标。HTTP／SSE 从物化结果、ring 和未落库尾段读取，不回到逐笔加载全天成交的旧实现。

行情缓存仅用于展示，不作为成交、借贷或强平的资金权威。启动补齐持久游标后的遗漏，停机排空并落库；纯行情后台任务继续运行。新开局清空旧市场数据后，按重建操作单保留 ID 高水位并处理浏览器待确认订单和 HTTP 历史缓存，防止旧数据串入新市场。

`/fx/pairs/{id}/chart`、`/history/fx/...` 和 `/fx/stream/{id}` 保留；新闻查询及 SSE news 字段移除。历史未就绪返回可重试状态，不伪造价格或成交量。接口字段见 [API 文档](api.md#12-幻想外汇-fx)。

## 发布与恢复

本次清理 revision 会物理删除废弃表列。普通部署应先拒绝带旧干预 schema 的源库；使用独立新库完成用户白名单导入和核对后再切换。旧数据库只有在备份可恢复、新库验证完成后才进入最终删除步骤。

仓库早期 Alembic baseline 为 stamp-only，新空库采用项目现有的当前 metadata 建表后 stamp head；不能直接假设空库 upgrade head 可建立全部历史表。重建工具先验证空目标，再执行建表与版本标记，禁止对源库运行 init_db。

降级 migration 只能重建空结构，不能恢复新闻或历史数据。新库已接受交易后不能直接切回旧库丢掉新账；数据恢复使用备份与明确的恢复方案。
