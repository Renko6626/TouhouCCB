# FX 恒定乘积 AMM 运维说明

FX 使用金圆券与外币的恒定乘积 AMM。央行目标价、随机游走、噪声订单、新闻冲击和 FX 新闻模块已移除；没有真实成交或人工流动性调整时，池价不会自行变化。

本次使用[业务重置](business-reset.md)建立新基线，保留账号身份和完整称号，清空旧经济与兑换业务。真人现金采用源库 initial_balance；经济开关保持关闭。

## 代码与存储

| 职责 | 入口 |
| --- | --- |
| AMM 数学和金额精度 | `backend/app/services/fx/amm.py`、`quantize.py` |
| 现货成交、开空和回补 | `fx/trading.py`、`fx/shorts.py` |
| 统一买卖报价、原子跨零、请求回执 | `fx/net_trading.py` |
| 注资与撤资 | `fx/liquidity.py` |
| 行情增量、缓存、K 线落库 | `fx/market_state.py`、`market_reads.py`、`candles.py`、`candle_flusher.py` |
| 账户估值与强平 | `backend/app/services/credit/` |
| 管理接口 | `backend/app/api/v1/admin_fx.py` |

`fx_pair` 保存池子储备、费率、开盘元数据和状态；`fx_treasury` 是系统借币库存和手续费账户；`fx_wallet` 保存现货；`fx_short_position` 保存外币欠款和锁定所得；`fx_trade` 保存真实成交；`fx_execution` 保存统一请求的规范化参数及完整成功回执，关联一至两条真实腿。`fx_event` 表及目标价、干预日预算列已删除。

## 开市与注资

新库导入后先保持交易、贷款和自动执行相关开关关闭。管理员通过现有后台创建市场并检查账户、库存和费率，再按活动方案开放交易。

- 创建输入保留币种代码、名称、初始储备、开盘元数据和手续费。前端通过开盘汇率及池子规模换算储备，实际价格以量化后的储备比值为准。
- 手续费范围 `0 <= rate < 1`，金额最多 6 位小数，池子两侧储备必须为正。`initial_price` 不构成未来价格上下界。
- 管理端最多同时开放 3 个交易对；开市后币种代码不可更改，名称可修正。
- 注撤资只走 `POST /api/v1/admin/fx/pairs/{id}/fund` 和 `/withdraw`，请求为 `gold_amount/foreign_amount`。禁止手改储备绕过锁、版本和审计。
- 现有发行规则保持：创建／注资分别向池子和 treasury 增加相应数量，两者余额分别展示。借币库存不是池子储备的另一种显示，不能混算。
- `fx_enabled` 与 `fx_short_enabled` 继续控制普通成交和新增空头。可借库存和账户风控继续约束开空。旧列及管理员 API 字段 `short_lending_limit_foreign` 保留兼容，但不再生效；旧值为 0 也不再阻止新增空头。停止开空须使用现有全局开空开关或品种状态，管理页面已移除上限设置。

七项旧干预配置已删除：`fx_hourly_sigma`、`fx_step_max_ratio`、`fx_noise_interval_sec`、`fx_noise_pool_ratio`、`fx_system_half_life_sec`、`fx_default_price_move_limit`、`fx_daily_budget`。新闻和事件 API 已移除，不再有定时事件或干预后台任务。

## 借贷和强平

保留真实借款／借币及全仓信贷内核：做空借出 treasury 外币并卖入同一 AMM，所得计入现金但锁定用于回补；回补买足欠币归还。锁定所得不能重复当作可用现金。每次真实成交在数据库事务内重新报价，保留滑点限制、幂等键、行锁和提交后通知。

统一信贷启用时，FX 与预测市场共享权益；展示采用边际价，风控采用实际可清算价值。传统模式和统一模式的准入差异沿用既有规则，详见[统一信贷说明](unified-credit-risk-2026-10.md)。

强平仍由定时扫描发现候选，分页批量估值、限并发执行、锁内重新检查。一次价格更新不会触发全量强平。扫描间隔及部分清算比例本次不调参；后续性能优化另行评估，不能把本次删引擎理解为已实现新的风险缓存或清算队列。

暂停和 reduce_only 继续使用既有状态语义。归档／删除仍检查用户持仓和外币义务；有交易历史的市场使用归档。已经移除的新闻表不参与市场清理判断。

## 行情和历史

复用 main 的增量行情实现：提交后的真实成交按 pair 游标消费，维护内存 ring；每 5 秒批量写入 K 线和持久游标。HTTP／SSE 从物化结果、ring 和未落库尾段读取，不回到逐笔加载全天成交的旧实现。

行情缓存仅用于展示，不作为成交、借贷或强平的资金权威。启动补齐持久游标后的遗漏，停机排空并落库；纯行情后台任务继续运行。新开局清空旧市场数据后，按重建操作单保留 ID 高水位并处理浏览器待确认订单和 HTTP 历史缓存，防止旧数据串入新市场。

`/fx/pairs/{id}/chart`、`/history/fx/...` 和 `/fx/stream/{id}` 保留；新闻查询及 SSE news 字段移除。历史未就绪返回可重试状态，不伪造价格或成交量。接口字段见 [API 文档](api.md#12-幻想外汇-fx)。

## 发布与恢复

本次清理 revision 会物理删除废弃表列。普通部署应先拒绝带旧干预 schema 的源库；使用独立新库完成用户白名单导入和核对后再切换。旧数据库只有在备份可恢复、新库验证完成后才进入最终删除步骤。

仓库早期 Alembic baseline 为 stamp-only，新空库采用项目现有的当前 metadata 建表后 stamp head；不能直接假设空库 upgrade head 可建立全部历史表。重建工具先验证空目标，再执行建表与版本标记，禁止对源库运行 init_db。

降级 migration 只能重建空结构，不能恢复新闻或历史数据。新库已接受交易后不能直接切回旧库丢掉新账；数据恢复使用备份与明确的恢复方案。

## 验证

实施验证使用隔离数据库，覆盖 AMM、现货／空头／回补／强平、注撤资、用户迁移、schema 及行情。实际命令与结果见本次实施记录；[旧行情性能记录](fx-market-data-performance-validation-2026-10-01.md)仅证明当时的代码，不作为本次性能承诺。UI 默认仅构建、已有测试和必要截图。


## 统一买卖与请求恢复

正式页面常规买卖走认证 net API。卖出先平多，再借币开空；买入先按统一时点回补含息欠币，再买入多头。
费用和储备顺序沿用既有AMM，整笔 min_out 保护总产出。新金债须明确确认，只用于新增多头；本仓锁金可用于回补，其他仓锁金不能花。
增仓只对最终组合准入一次，纯减仓不追加初始保证金要求。全停与只减仓仍按既有状态语义执行。

页面用350ms防抖报价，30秒提示，账户/输入/币种变化废弃旧报价；行情SSE不逐帧重做组合估值。
报价时的账户版本及增仓许可进入请求，报价显示纯减仓时不能因随后池价变化静默开仓。
快速全部卖出/全部回补保持只平仓；未知结果按账号保存原参数与编号，恢复前阻止新交易。
成功回执与账户刷新分开，刷新失败不会把已成交标为失败。私人历史按请求分组，可查看真实腿；真实腿limit若切到最旧net组中间，后端补齐其同用户同币种兄弟腿，正常最多多返回一条。

net、旧融资和旧空头入口共用前端待确认订单逻辑，保留各自原有存储前缀与 API 路由。记录损坏或无法清理时，用户可查看成交记录、核对账户，再勾选确认并清除本地待确认记录；该操作不撤销成交，也不修改账户。提交期间不能清除，存储清除失败继续阻止新交易。存储仍不可用时需恢复浏览器存储并刷新页面，不自动重试订单。

旧API保持原动作与回放；旧融资/空头pending仍用原路由恢复。已有同币种正钱包与含息欠币异常会明确阻塞统一入口，须人工查账，不自动净额迁移。
迁移只在可丢弃测试库验证；有成功回执的数据库拒绝丢失请求身份的降级。生产迁移及部署仍需后续明确授权。
本次验证见[统一多空实施记录](fx-net-trading-validation-2026-10-11.md)。限价单、资金预留和扫描任务留待独立方案。

## 报价与成交读取精简（2026-10-12）

统一报价合并读取币种、账户、钱包和金库；成交合并查询请求回执与旧请求编号，保留原有锁、回放和事务边界。取消全体玩家合计借币本金上限及其汇总查询，实际金库库存和个人风险检查继续生效。现货、开空和回补仍调用已有账务服务。

隔离 PostgreSQL 对照中，普通报价吞吐中位数提高15.8%～42.6%，有债报价提高3.8%～21.8%；成交结果有升有降，未证明稳定提速。测试未包含网络和后台任务，不能视为线上容量上限。查询计数、测试和兼容说明见[读取精简验证记录](fx-read-cost-validation-2026-10-12.md)，逐场景吞吐与延迟见[吞吐对照记录](fx-throughput-validation-2026-10-12.md)。

后续待办：输入时采用本地预览，确认前再取完整后端报价，成交保留锁内风控和资金检查。所需快照、误差边界和实施前决策已记录在[读取精简计划的本地预览待办](superpowers/plans/2026-10-12-fx-read-cost.md)，用户暂缓实施。

## 管理员资金操作与统一价格事件（2026-10-13）

管理页提供固定数量注资／撤资预览，分别展示交易池与系统金库的预计余额，以及储备比值对应的池价和变化。预览读取当前快照，不锁价；执行继续走原资金入口，在锁内检查最新余额。草稿、暂停、关闭但未归档的市场仍可调整资金，页面显示玩家是否可交易。管理员操作记录按 keyset 分页读取，备注和审计仅向有权限的管理员展示。

提交成功后先展示执行结果，再刷新市场和操作记录；刷新失败保留成功结果。网络异常导致执行结果不明时，先刷新并核对操作记录，不自动重发资金请求。

`fx_pool_event` 统一保存发行、注资、撤资和真实成交的储备变化，来源分别关联资金审计或真实成交；跨零的两条真实腿各有一条事件。提交后的通知只负责唤醒消费者，事件与账务在同一事务内持久化。K 线按事件前后储备确定 OHLC；`volume` 仍是金圆券真实成交量，买入计金圆券输入、卖出计金圆券输出；发行、注资和撤资的成交量和成交笔数为零，但增加 `n_events`。因此零量蜡烛也可能改变池价。没有真实操作时不在事件存储中生成周期性价格事件或合成水平桶。

图表和历史继续读取物化 K 线、分档 ring 和有界尾段；事件消费每页 1,000 条，后台每轮最多 10 页后重新排队。HTTP／SSE 未聚合尾段超过 10,000 条时返回可重试的历史未就绪状态；输出及细粒度源桶上限均为 20,000。ring 按每档自己的保留窗口暖启动，公共增量缓冲上限 512。公开事件不包含储备、管理员身份、备注、审计或玩家私人数据。

当前新基线直接包含池事件 schema；在线消费同事务写入的事件，不再执行历史来源转换或手工 FX 回填。旧工具与旧 migration 在[归档索引](archive/database-pre-baseline-2026-10-13/README.md)中只供查阅。旧数据库切换遵循[业务重置操作单](business-reset.md)。

事件行数随真实操作数增长，第一版不自动删除原始事件；运维应记录行数、表和索引大小。上线迁移、停写、部署、历史取舍和开市须另行安排。本轮隔离 PG 对照、迁移、检查及截图范围见[管理员资金与行情验证记录](fx-admin-events-validation-2026-10-13.md)，结果不构成线上容量承诺。
