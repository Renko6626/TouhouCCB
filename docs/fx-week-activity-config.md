# FX 一周活动参数草案

记录日期：2026-09-30。

本草案用于约 50 名群友参与的一周 FX 活动。目标是让普通玩家有波段交易空间、群体买卖能推动行情，少量黑天鹅产生戏剧性变化，同时给玩家判断和减仓的时间。参数来自现有 AMM、统一信贷与系统干预代码的受控情景测算，属于首轮试跑建议，不代表线上已应用的配置或多人行为仿真结果。

## 1. 场景与时间假设

用户确定的条件：

- 约 50 人，每人初始 500 金圆券，总初始本金 25,000 金圆券。
- 初始汇率为 1 外币 = 0.2 金圆券。
- 最高可能使用 10–20 倍名义杠杆，平均预计不超过 5 倍。
- 活动持续一周；参与者是群友，不会长时间持续关注，可能采用固定交易窗口。

本草案进一步假设：

- 先集中运营一个 FX 币种。
- 每天主交易窗口暂按北京时间 20:00–22:00，共约 14 小时活跃时间；具体时段尚未确定。
- 普通新闻带动日内波段，黑天鹅约每周两次。新闻具体方向、内容和发布时间待运营安排。
- 杠杆参数以已启用统一信贷模式为前提。平均 5 倍是参与行为假设，不是代码强制限制。

按初始本金静态计算，全体平均 5 倍对应约 125,000 金的理论名义仓位，全部 20 倍对应约 500,000 金。它们不是每日成交额上限，也未计手续费、准入缓冲及盈亏后的权益变化。

## 2. 币种与池子

| 参数 | 建议值 | 用途 |
| --- | ---: | --- |
| `initial_price` | `0.2` | 初始参考价，金圆券/外币 |
| `target_price` | `0.2` | 初始系统目标价 |
| `gold_reserve` | `2000000` | 金圆券池子深度 |
| `foreign_reserve` | `10000000` | 保证实际初价 G/F = 0.2 |
| `target_min` | `0.1` | 系统目标下限 |
| `target_max` | `0.4` | 系统目标上限 |
| `buy_fee_rate` | `0.0005` | 每侧 0.05% |
| `sell_fee_rate` | `0.0005` | 每侧 0.05% |

目标区间约束系统目标价，不是玩家成交价涨跌停。当前代码还要求目标价处于初始参考价的 0.5–2 倍范围内；本方案的两层边界一致。

创建币种时，当前实现还会配发与池子同额的系统 treasury：2,000,000 金与 10,000,000 外币。交易池与 treasury 分开记账；日预算不会自动补充任何一侧储备。

### 买入推动价格的幅度

以下使用实际 `quote_buy`、初始汇率 0.2 和买入费率 0.05%计算。输入为单向累计买入金圆券，期间没有卖出、系统干预或注撤资。百分比是成交后边际价格变化，不是平均成交滑点。

| 买入金圆券 | 50 万金池 | 100 万金池 | 推荐的 200 万金池 |
| ---: | ---: | ---: | ---: |
| 500 | 0.20% | 0.10% | 0.05% |
| 2,500 | 1.00% | 0.50% | 0.25% |
| 10,000 | 4.04% | 2.01% | 1.00% |
| 25,000 | 10.24% | 5.06% | 2.51% |
| 125,000 | 56.22% | 26.55% | 12.88% |

200 万金池保留个人订单的影响，并让多人追涨产生可见行情。较浅的 50 万金池容易放大大户交易和强平冲击；过深的池子则会减弱群体买卖的影响。这是参数取舍，尚未测量实际玩家交易行为。

## 3. 日常行情与系统干预

| 配置 | 建议值 | 预期作用 |
| --- | ---: | --- |
| `fx_hourly_sigma` | `0.015` | 目标对数价格小时波动率 1.5% |
| `fx_step_max_ratio` | `0.001` | 目标价每个 tick 最多相对变化 0.1% |
| `fx_system_half_life_sec` | `1800` | 固定目标且可持续执行时，约 30 分钟消掉一半对数价格偏离 |
| `fx_default_price_move_limit` | `0.001` | 常规干预单步价格变化及订单规模限制 |
| `fx_noise_interval_sec` | `30` | 噪声订单平均等待时间 30 秒 |
| `fx_noise_pool_ratio` | `0.0002` | 噪声目标价格扰动及订单投入池比例上限参数 |
| `fx_daily_budget` | `400000` | 每个货币对每天的系统订单金圆券名义额度 |

目标价每 5 秒随机走一步；新闻进行期间暂停普通随机游走。新闻会改变目标价，结束后从新目标继续游走，不自动回到原来的 0.2。实际池价仍由 AMM 储备、玩家交易与系统订单共同决定。

`fx_default_price_move_limit` 限制常规系统干预，不是玩家订单或新闻事件的统一涨跌停。半衰期也不能保证实际价格按时回归：目标价变化、玩家交易、金库余额和预算都会影响执行。

### 每日预算依据

日预算同时覆盖常规目标干预、噪声订单和新闻事件，玩家成交不消耗此额度。系统买入按投入金圆券计算；卖出按外币投入乘成交前汇率折算，衡量累计名义额度，不是金库净亏损。按 UTC 日期重置，北京时间为 08:00。

以初始 200 万金池、无其他订单计算：

| 情景 | 系统订单所需金圆券名义额度 |
| --- | ---: |
| 价格上涨 2% | 约 19,901 |
| 价格下跌 3% | 约 30,692 |
| 价格上涨 8% | 约 78,461 |
| 价格下跌 8% | 约 85,144 |
| 两小时噪声，按平均间隔与小扰动估算 | 约 48,000 |

每日 400,000 的建议为新闻、噪声及玩家集中交易后的常规干预留出余量，并不是按最高杠杆机械放大，也不要求每天花完。噪声实际次数受随机等待、5 秒 tick 和执行失败影响，上表不是精确每日支出预测。

## 4. 统一信贷与强平

| 配置 | 建议值 | 说明 |
| --- | ---: | --- |
| `initial_balance` | `500` | 新用户初始本金；不自动重置已有用户余额 |
| `credit_leverage` | `20` | 名义杠杆上限，普通参与建议以 3–5 倍为主 |
| `credit_maintenance_ratio` | `0.025` | 维持率按净清算权益/债务定义 |
| `loan_daily_rate` | `0.0001` | 日利率 0.01% |
| `liquidation_enabled` | `true` | 启用强平扫描 |
| `liquidation_sweep_interval_sec` | `10` | 每 10 秒扫描，实际还受执行耗时影响 |
| `liquidation_partial_pct` | `0.05` | 正权益账户每批卖出选中组约 5% |

本表仅适用于统一信贷模式。`credit_leverage=20` 对应初始门槛 `R_initial=1/19≈0.05263`，严格高于维持率 0.025；初始率也是强平恢复门槛。不要把旧的 `loan_leverage_k` 填成 20。统一信贷开关、杠杆和维持率按启动缓存读取，修改后需重启才能生效。

强平每次扫描最多为同一用户处理一个资产组。持续未恢复时，后续扫描可继续卖出；5%不是整个强平过程的总卖出上限。清算净值不大于零时会改用全量卖出所选组。

### 单一 FX 持仓的风险尺度

以下为受控情景：每人本金 500，将本金与借款全部投入一个 FX 币种，无剩余现金或其他资产；费率与池子按本草案。入场后价格额外下跌时，保持池子恒定乘积，用实际 `quote_sell` 全仓净回收额计算清算权益，求维持率 0.025 的触发点。

| 理论名义杠杆 | 汇率相对入场后池价额外下跌约多少会触发强平 |
| ---: | ---: |
| 5 倍 | 17.93% |
| 10 倍 | 7.67% |
| 20 倍 | 2.53% |

20 倍是理论风险测算：未给手续费预留准入缓冲，不表示当前接口允许恰好借满后全部买入。实际可用仓位、其他资产、利息与其他玩家订单都会改变触发点。这些数字不能预测多人强平人数或穿仓规模。

### 一周利息负担

按债务持续七天且不还款、日复利 `(1+r)^7` 计算。名义杠杆 L 的初始债务为 `(L−1)×500`，下表为新增利息占初始 500 本金的比例：

| 日利率 | 5 倍 | 10 倍 | 20 倍 |
| --- | ---: | ---: | ---: |
| 推荐 `0.0001`，即 0.01% | 0.28% | 0.63% | 1.33% |
| `0.0002`，即 0.02% | 0.56% | 1.26% | 2.66% |
| `0.005`，即 0.5% | 14.21% | 31.98% | 67.51% |

推荐较低利息，让一周胜负主要由交易判断决定，而不是由长时间离线积累的利息决定。关交易总闸不停止现实时间计息。

## 5. 新闻与节目节奏

每天建议发布 1–2 条新闻，黑天鹅替换其中一条，而不是额外叠加大量事件。

| 类型 | 目标价冲击 `shock_ratio` | 首轮反应 `first_reaction_ratio` | 窗口 `window_sec` | 预算 `budget` |
| --- | --- | --- | --- | ---: |
| 普通新闻 | ±0.02–0.03 | `0.2` | `600` | `40000` |
| 黑天鹅，约每周两次 | ±0.06–0.08 | `0.1–0.15` | `900–1200` | `120000` |

冲击比例改变的是系统目标价，不保证池价精确完成相同幅度。首轮反应比例控制对数价格差的推进比例，不是“首单只能花总预算的这些比例”。事件预算不足、玩家反向交易和金库余额都会改变实际行情；事件结束后常规干预仍可使用日预算向新目标靠拢。

主交易窗口可暂按以下节奏组织：

1. 20:00–20:15 开盘与观察，让玩家建立仓位。
2. 20:20 左右发布一条普通新闻。
3. 21:00 左右发布第二条新闻；一周中约两天替换为黑天鹅。
4. 最后半小时留给调整持仓，不再发来不及结束的新事件。

新闻具体时间、方向和先后顺序不固定，不必每天机械地涨跌抵消。公共新闻正文提供可供判断的信息；冲击比例、预算与目标价继续仅管理员可见。黑天鹅用 15–20 分钟展开，让高杠杆玩家有机会判断或减仓。

## 6. 固定交易窗口的操作边界

- 主窗口内按运营安排开启 `fx_enabled`；窗口外建议关闭总闸，停止玩家成交和系统订单。该开关影响所有 FX 币种；此处按单币种活动假设。
- 收盘前让已发布事件结束，排期放在可完整覆盖事件窗口的时间段内。本文不包含自动开关盘任务的实现。
- 带债持仓不要用普通 `paused` 或 `closed` 冻结：统一风控把不可执行的 FX 持仓清算价值计为零，可能触发强平或阻塞清算。总闸关闭与资产状态关闭不同。
- 关闭总闸不免除利息，也不停止强平扫描。后台强平按内部执行路径处理，不能把“关盘”宣传为完全冻结账户。
- 恢复开盘不等于开启一套独立活动时钟：现有目标游走和干预会读取实际经过时间，开盘首个 tick 仍受单步限制；事件进度与利息也按真实时间计算。

## 7. 首轮验证与待办

本草案只完成定价、费用、利息和孤立账户的受控测算。正式活动前优先确认：

- 确定实际每日时段、是否严格关盘，以及 10 倍或 20 倍上限的最终选择。
- 观察试跑时的订单分布、价格偏离、预算消耗、强平扫描耗时及参与者是否有足够减仓时间。
- 验证多人集中买卖、连续新闻和强平卖出叠加时的行为；当前表格不能代替这类仿真。
- 修正目标价每 tick 向下截到六位小数造成的累积偏差。这是现有实现问题，参数无法彻底消除。
- 确定活动结束时持仓、债务与排名的处理规则；当前展示净值与可兑现清算净值不是同一口径。

后续做空更新见 [FX 做空与统一债务风控设计](superpowers/specs/2026-09-30-fx-short-debt-design.md)，状态为待审阅。本文风险测算仍是既有多头情景，不包含空头资金流、回补及多人双向强平；新增做空后须重新验证活动参数。做空 spec 的首轮 10 倍上限是较新的运营建议，也尚未应用。

## 8. 测算来源与复算口径

主要依据当前代码，旧 [摩拉参数与强平准备](fx-margin-preparation.md) 保留为历史讨论，不作为本活动参数的现行定义。

- [FX AMM](../backend/app/services/fx/amm.py)：手续费、买卖报价及储备变化。
- [FX 引擎](../backend/app/services/fx/engine.py)：随机游走、普通干预、噪声和预算名义额度。
- [FX 新闻调度](../backend/app/services/fx/scheduler.py)：目标价冲击、首轮反应与事件发布。
- [统一信贷门槛](../backend/app/services/credit/thresholds.py)：初始率、维持率及触发定义。
- [FX 风控报价](../backend/app/services/credit/fx_quote.py)、[组合估值](../backend/app/services/credit/valuation.py)：实际 AMM 净清算价值。
- [利息计算](../backend/app/services/loan_service.py)：按现实经过时间的日复利。
- [统一强平执行](../backend/app/services/credit/execution.py)：每批卖出、还款与恢复检查。

可独立核对的公式：

```text
单向净买入 g 金，初始金储备 G：
  P_after / P_before ≈ (1 + g/G)^2
  g = 投入金额 × (1 − 买入费率)，具体以六位金额量化结果为准

无其他订单，把当前池价乘以 r 所需的系统名义额度：
  上涨：G × (sqrt(r) − 1)
  下跌：G × (1/sqrt(r) − 1)

小扰动噪声额度估计：
  活跃秒数 / 平均间隔 × G × fx_noise_pool_ratio / 2

利息占初始本金比例：
  (L − 1) × ((1 + 日利率)^天数 − 1)
```

强平表使用实际 AMM 全仓卖出净额二分求解触发点，没有用“持仓数量 × 边际价格”替代清算价值。买入推动价格的结果还用上述恒定乘积公式独立核对，显示精度内一致。
