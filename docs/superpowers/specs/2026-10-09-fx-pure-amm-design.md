# FX 第一阶段：移除央行与新闻，重建数据库

日期：2026-10-09。状态：按用户最新选择修订的设计，配套计划待执行；未修改业务代码或数据库。

## 已确认的目标和数据路线

用户已明确：移除 FX 央行机制，新闻暂时关闭；重建整个数据库，仅迁移用户相关数据。保留登录身份、权限和个人资料；余额按新开局重置，旧持仓和债务清零。

实施基于最新 `origin/main`，本次检查的提交为 `1af6678`。当前工作区和落后的本地 main 不是实施基线。保留 main 已合入的 FX 增量行情、内存 ring、K 线批量落库和恢复功能，用于新开局的行情。

本修订取代旧版“保留文字新闻、保留废弃数据库列、兼容旧排期”的方案；不再实现文字新闻服务、历史事件状态转换或停用标识。

## 产品及代码范围

- 删除目标价随机游走、目标回归、噪声交易、事件首轮冲击和后续干预。
- 关闭全部 FX 新闻入口：管理端创建／排期／发布／取消、玩家新闻列表、历史读取、轮询及 SSE 新闻字段；旧新闻路由直接移除，返回正常 404，不保留假成功接口。
- 将注撤资函数从 `fx/scheduler.py` 迁到 `fx/liquidity.py`，保持资金算法、权限、锁序、审计和函数签名。
- 删除 `fx/engine.py`、`fx/randomness.py`、搬空后的 `fx/scheduler.py` 及应用中的启动／停止接线。行情 consumer、flusher、publisher 继续运行，不能误删其后台任务。
- 保留 AMM、手续费、现货、借币做空／回补、金圆券借款、全仓风控和强平执行能力；本阶段不调整它们的算法或频率。
- `FxTreasury` 继续作为借币库存和手续费账户；新开局重新注资，不能因删除央行把做空资金来源也删掉。
- 本轮不实现逐仓、统一交易窗口、挂单、止损、风险缓存或新的清算调度，不增加依赖／部署组件。

## 新 schema

删除 `FxEvent`／`FxEventStatus` 及 `fx_event` 表；删除 `FxPair.target_price/target_min/target_max` 和其约束；删除 `FxTreasury.daily_spend/spend_date`。删除七个干预配置键及默认播种、规则、API 和前端元数据：`fx_hourly_sigma`、`fx_step_max_ratio`、`fx_noise_interval_sec`、`fx_noise_pool_ratio`、`fx_system_half_life_sec`、`fx_default_price_move_limit`、`fx_daily_budget`。

`initial_price` 保留为开盘元数据，不限制未来价格。新建市场前端只需开盘汇率与池子规模来计算储备，删除涨跌范围；实际价格由量化后的储备决定。注资向池子和借币库存分别发行的既有账务本轮保留，页面分别显示两处余额。

删除历史干预控制和专用管理记录界面；系统强平成交仍正常展示。为避免无关重构，现有历史审计解释器不在本轮彻底重写，但新业务库不导入旧交易、新闻或干预审计。

追加清理 revision，使 Alembic 最终 schema 与当前模型一致，不改写既有迁移历史。仓库的 Alembic baseline 为 stamp-only，空库不能直接 upgrade。正式重建先证明目标无业务表，再按现有项目机制注册当前模型、create_all、stamp 实际 head 和播种默认配置；同时验证清理 migration 从旧 schema 升级后的结构与新模型一致。旧源库不运行该删除迁移。不在旧库调用 `init_db.py`、DROP ALL 或赛季重置脚本。

## 用户迁移清单

| 数据 | 处理 |
| --- | --- |
| 真人用户 id、casdoor_id、username、email | 保留；保留原 ID 和 SSO 绑定，迁移后修正序列 |
| is_active、is_superuser、tos_accepted_at | 保留，停用账号不得意外恢复、普通用户不得提权 |
| cash | 重置为迁移清单中明确列出的新开局金额 B；默认建议沿用源库 initial_balance，切换前展示实际数值；缺失或无效时必须显式指定，不能猜测 |
| debt、debt_last_accrued_at、last_liquidated_at | 分别置 0、NULL、NULL；清空旧经济冻结状态，economic_version 以新账户初始值开始 |
| LMSR 持仓、FX 钱包／空头、锁定所得、强平 run/action | 不导入；新开局全部为零／空 |
| 称号及佩戴关系 | 作为个人资料列入保留清单；连同引用的称号定义和已使用兑换标识迁移，避免悬空引用或重复领取 |
| 已购兑换码、未完成履约、弹幕兑换等用户权益 | 列入保留清单供切换前核对；默认保留已购权益及其必要外键／审计依赖，不导入无关未售库存。删除这些权益须另行明确，不能由“旧交易清空”推断 |
| bot 用户／配置、旧市场、成交、行情、新闻、游戏账务历史 | 不作为新开局业务数据导入；旧库备份保存。若保留权益引用 bot／管理员等账号，预检列出最小依赖，再确定保留停用引用账号，不能禁用外键硬导入 |
| 全站配置 | 按新版本默认值初始化，只复制迁移清单明确列出的必要站点参数；不整表复制旧配置，不恢复干预键 |

这不是整行复制 User：该表同时包含身份和旧债务。导出和导入均按字段白名单处理。导入后按现有审计格式写入新开局用户余额锚点，不伪造旧交易已结算，也不使用旧持仓边际价计算新余额。

“重建整个数据库”也包含旧 LMSR 活动数据重置；只迁移已选的用户数据和必要依赖。预测市场等产品代码仍保留。称号和兑换依赖的实际范围要由只读导出报告列明，在正式切换前完成核对；这不阻塞本阶段代码清理。

## 重建与切换

1. 在开发隔离库完成新 schema、白名单导出／导入工具和恢复演练。
2. 正式执行前固定源库、空目标库、代码 SHA、用户保留清单和金额 B。源库与目标库必须不同，目标非空必须拒绝导入；连接信息不输出密码。
3. 停止旧后端和所有写入者，制作一致备份并验证可恢复，再导出用户数据。迁移文件限制文件权限，不把身份信息、邮箱和兑换码写入仓库或普通日志。
4. 在新库建表、播种、导入；按白名单比对账号、SSO、权限、资料和权益，核对余额与零债务、无旧持仓、外键和序列；写入新开局审计锚点。
5. 新库初始 FX／做空／贷款／强平／PvE 交易能力保持关闭。执行者先核对实际开关和环境门闸；新市场注资和开市另行准备，不沿用旧 gate 状态自动开放。
6. 切换应用到验证后的新库；旧数据库在切换验证前保留。旧库物理删除单列为最终操作，核对库名及备份后执行；不能在导出前先删唯一源库。
7. 重建会复用市场 ID：沿用旧序列高水位或清除相关 history HTTP／nginx／浏览器可复用缓存并更换历史版本，覆盖 FX 和 LMSR；重启 writer/ring、清理浏览器旧待确认订单的跨开局恢复风险。

不同时支持旧数据库直接热升级。普通部署自动 upgrade 旧库会删除新闻表，正式发布必须使用这条新库切换流程。清理 migration 的 downgrade 只能重建空的已删结构，不能恢复丢失内容；恢复数据使用备份，不能把 downgrade 当数据恢复。

## 验证与交付
