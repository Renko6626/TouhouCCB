# FX 统一多空交易设计

日期：2026-10-11。状态：业务原则、统一接口及多段成交回执已于2026-10-11批准，实施和隔离库验证完成；生产迁移与部署未执行。

关联：[实施计划](../plans/2026-10-11-fx-net-trading.md)、[现有 FX 运维说明](../../fx.md)、[现有空头设计](2026-09-30-fx-short-debt-design.md)。本设计只调整玩家反向交易的处理方法；既有库存、锁金、授信及风控规则继续适用。

## 1. 已确认的业务原则

- 同一用户同一币种，反向操作先平已有仓位，超过已有仓位的部分再开反向仓位。
- 支持一笔请求跨过零仓位；整笔成功或失败，后半段失败不能留下前半段成交。
- 每次成功提交后，同 pair 的正钱包与正欠币不能同时存在。空头数量采用统一时点的含息欠币，不只看本金。
- 底层保留非负 `FxWallet` 和独立 `FxShortPosition`，不把钱包改成可以为负的仓位表。
- 复用现有恒定乘积 AMM、手续费、Decimal 精度、计息和估值公式。新增交易拆分、模拟及事务编排，不新增撮合算法。
- 不把手续费改成零，不引入净额授信优惠，不改变全账户保证金门槛。
- 限价单放在统一交易完成之后，本期不实现挂单、资金预留或挂单 scheduler。

以下按实际外币成交量说明方向，买入输入单位另见接口提案：

| 初始状态 | 实际操作 | 提交后状态 |
| --- | --- | --- |
| 多头 100 | 卖出 40 | 多头 60 |
| 多头 100 | 卖出 100 | 空仓 |
| 多头 100 | 卖出 140 | 先卖自有 100，再借币卖出 40，空头 40 |
| 空头含息欠币 100 | 买得 40 | 归还 40，欠币剩 60 |
| 空头含息欠币 100 | 买得 100 | 完整回补，空仓 |
| 空头含息欠币 100 | 买得 140 | 先归还 100，剩余 40 入钱包，多头 40 |

## 2. 已确认的接口与回执方案

### 2.1 统一报价与成交入口

推荐新增已认证的 `POST /fx/pairs/{id}/net/quote` 和 `POST /fx/pairs/{id}/net/trades`。保留原现货、融资、开空、回补接口的请求语义和成功回放，不让旧客户端的同一请求突然从“仅卖现货”变成“余额不足就借币”。新前端常规下单使用统一入口；现有全部卖出／全部回补快捷操作继续限定为平仓，不反向开仓。

推荐保留当前金额输入单位，降低 UI 与融资功能的改动：

- 买入：`side=buy`，`amount` 为金圆券总投入（含手续费），`min_out` 为整笔最低外币所得。
- 卖出：`side=sell`，`amount` 为外币总卖出量（含手续费），`min_out` 为整笔最低金圆券所得。
- `borrow_amount` 默认 0，只能在买入时显式填写；表示本次同意新增的金圆券本金，不自动补足资金缺口。
- 成交增加 `idempotency_key`、报价返回的 `expected_economic_version` 和按报价增仓量确定的 `allow_growth`（默认 false）。先回放成功请求，再检查新请求的账户版本；报价后账户变化时拒绝并要求重新确认，避免原本显示为平仓的操作意外变成开仓。池价格变化仍由锁内重报价和整笔 min_out 保护；原报价纯减仓而价格变化后出现增仓时，allow_growth=false 返回409要求重新确认。
- 金额仍为十进制字符串、最多六位小数，复用现有存储范围校验。

另一种方案是买卖都输入外币数量：边界直观，但会改变现有金圆券金额／本金倍数输入与融资报价契约。本提案推荐保留现有单位；前述“买得 140”是报价结果，不是把 140 金圆券当作 140 外币。

### 2.2 一个请求、多段真实成交

当前 `FxTrade` 的 `(user_id,idempotency_key)` 唯一约束只能对应一条成交，无法直接承载两段成交。推荐增加最小的 `FxExecution` 成功回执：保存用户、pair、原请求编号、规范化请求参数、响应版本、已物化响应与时间；一条回执关联一至两条真实 `FxTrade`。

- 回执使用独立主键，用户／pair 外键和 `(user_id,idempotency_key)` 唯一约束；请求编号沿用最长 128 字符，请求／响应以 JSON 保存 Decimal 字符串。
- `FxTrade` 增加可空的 `execution_id` 和 `execution_leg`；旧记录不变，关联腿使用已有 purpose，唯一约束覆盖 `(execution_id,execution_leg)`。
- 新腿的旧 `idempotency_key` 置空；原始编号保存在回执中，不用拼接用户编号生成内部腿编号。
- 原请求编号仍是全 FX 的同用户命名空间。新旧写入口均在 User 锁内检查回执和旧成交；跨入口占用编号返回 409。原成功请求按保存的请求类型及参数回放。
- 回执、真实成交、资金和审计同事务提交。明确失败不保存成功回执；不存在提交了一半的执行状态。
- 私人成交历史可按回执分组，公开成交／行情仍只消费真实腿，不额外生成汇总成交导致双倍成交量。

相较把复杂拆分塞入一个新 purpose 的汇总成交，这个方案能保留既有每条真实成交的 purpose 和储备轨迹，但会增加一张回执表及关联列。回执只解决立即成交的原子性与重试，不是未来挂单表。新增存储与接口已按项目约定确认并在隔离工作树实施。

## 3. 报价与结算

### 3.1 卖出

设自有外币 `W`、请求外币量 `A`：`spot_sell=min(W,A)`，`short_open=A-spot_sell`。

先报价并执行现货卖出，再用其成交后储备报价借币卖出。只为 `short_open` 检查实际借币库存、借出上限、开空开关和增险准入。现货卖出所得继续优先偿还金圆券贷款；新增空头所得按现有规则计入现金并锁定，不能被前段还款消费。

### 3.2 买入

设买入金圆券预算 `B`、统一时点 T 的含息欠币 `Q`：

1. `Q=0`：复用普通现货／显式融资买入。
2. `Q>0`：先用 `quote_buy_exact_out(Q)` 判断完整回补的成本 `X`；无法完整报价不代表禁止当前允许的部分回补。
3. `B<=X`，或完整回补不可报价：用 `quote_buy(B)` 的实际外币产出回补，实际归还量不得超过 Q；不创建钱包多头。边界 B=X 使用完整回补报价，消除欠币尾差。
4. `B>X`：先按 exact-output 买足 Q 并完整归还，再将剩余预算 `B-X` 用于现货买入。每段费用与精度都按真实成交计算，不把两次向上取整改成一次以凑理论等价。
5. 剩余预算无法产生合法正数量时整笔明确拒绝，不偷偷扩大预算或生成零数量成交；全部回补快捷操作走原 `cover_all` 契约，不强制花完额外预算。

普通买入不得使用其他空头锁金。回补可使用本仓锁金与未锁现金，完整回补后释放的现金可以承担后段现金买入。显式融资只用于新增多头段：新增本金不得超过该段投入；回补资金在加新借款前就必须足够。纯回补不能借新金圆券完成，借币利息先于本金归还。

### 3.3 整笔保护与风控

- `min_out` 保护整笔外币／金圆券总产出，不把同一个阈值重复要求每段达到；报价返回各段拆分及总额。
- 同一 T 结清相关旧息，新借款从 T 起息。手续费、钱包成本、空头收益基准、锁金按各段分别入账。
- 先模拟整笔结果，判断实际减仓段和增仓段，再应用既有状态和开关规则。开空／贷款关闭、信用冻结不应阻止其原本允许的纯减仓；出现任何新增风险时执行完整组合准入。
- reduce-only 下不能跨零开新仓，不静默截断整笔请求；全暂停的语义沿用原规则。
- 有增仓时按整笔最终储备、钱包、欠币、现金和金债做一次权威增险判定。纯减仓保留当前回补在低保证金或估值阻塞下的允许条件，不强加初始门槛。
- 普通无债现金路径不因统一入口默认加载全组合；有欠币、融资或新增空头才取得必要依赖。

## 4. 事务、兼容性与估值

复用单写所有权、完整有序 GATES、品种先于 User 的行锁顺序。发现依赖后释放 discovery 事务，再一次获取目标独占和其他依赖共享门闩；等待不占连接。锁内重验版本、重报价、查重，再模拟与结算。版本冲突全回滚、释放后有限重试；不在 User 锁下补拿品种门闩。

当前 in-session 函数可以复用，但不能简单调用两个各自有 gate／commit 的 HTTP wrapper，也不能原样叠加两个完整风控与借款检查。局部提取不 commit 的结算辅助函数，旧入口仍走原校验，新入口拥有整笔准入、事务及回执。

commit 前物化响应；提交后一次唤醒行情 consumer、按实际成交发布。失败或回放不新增 K 线、成交量或发布。行情依然消费真实 FxTrade 行，停机恢复机制不变。

成功提交后每个 pair 仅一条有效方向，因此继续使用多头卖出净额／空头含息回补成本估值，不引入多空联合清算数学。统一后态的储备必须供所有估值腿读取，避免现有 `fx_reserves`／`short_reserves` 的不对称在编排中遗漏。

既有历史和数据库不清空。发现同 pair 正钱包与正欠币的异常数据时，拒绝新增统一交易并报告具体记录；不要自动免债或启动钱包直接还币迁移。本期不新增“钱包直接偿债”功能，因为正常反向交易已经通过先平仓保持单方向。

## 5. 页面与范围

正式 FX 页面提供统一买入／卖出操作，报价明确展示“回补多少、买入多少”或“卖出现货多少、新增空头多少”，尤其提示跨零、新增欠币、融资和锁定所得。下单前看完整结果，不把卖出全部现货按钮变成借币入口。保留本金倍数／融资显式确认、现有黑白布局与图表，不重做整页。

成交回执区分实际平仓、开仓、贷款及自动还款；私人历史按请求分组并允许查看真实腿。未知结果按账号持久化原参数与编号，恢复前阻止新交易；账户刷新失败不得把已成功成交报成失败。

限价单单列后续项目：复用统一入口，不预留、触发后一次逻辑尝试、明确业务失败终止；计划中的扫描基线为每 10 秒至多 50 张并公平轮转。每用户最多 3 张有效单是此前的推荐值，后续再固定配置与完整契约。本期不创建挂单表、后台任务或挂单 UI。

## 6. 验收边界

定向覆盖零前后状态、费用／利息／尾差、后段拒绝完整回滚、同编号重放与并发、锁金用途、旧入口兼容、行情不重复计量。复用现有生产逻辑及夹具，在最合适的层补覆盖，不在各层复制全部场景。

UI 默认仅构建、已有测试及必要截图；不自动点击、填表或真实资金操作。迁移仅在可丢弃测试库验证，未提交推送或部署。真实命令、结果和未验证范围见[实施验证](../../fx-net-trading-validation-2026-10-11.md)，未将历史99项通过记录当作本次验收。
