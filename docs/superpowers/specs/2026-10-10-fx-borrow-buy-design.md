# FX 借款并买入：接口与页面配套草案

日期：2026-10-10。状态：用户已确认方案并授权实施、提交推送和自动部署；性能约束随方案一同执行。

## 已确认范围与现状

用户确认先做 FX 外汇交易页，解决杠杆和融资来源不明确的问题，加入“借款并买入”API 并准备配套。

- 真实页面 `thccb-frontend/src/pages/Fx.vue` 仍提示“请先借款，再确认做多”。
- `/fx-preview` 仅为内存样稿，其目标账户杠杆、固定价格和 Number 运算不能直接用于真实交易。
- FX 已有现货成交、开空、回补的请求去重，统一信贷已提供全组合交易后风险检查。
- 贷款和 LMSR 的全站请求编号仍按原待办延期；本功能只沿用 FX 的请求去重机制。

## 推荐方案与取舍（尚待确认）

保持 FastAPI、SQLAlchemy/SQLModel、PostgreSQL/SQLite、Vue/Pinia 和现有 FX AMM，不增加依赖、订单系统或独立贷款申请表。

新增专用融资买入接口，内部复用现有 FX 成交逻辑、信贷风控、贷款流水和提交后发布。相较于前端先调用借款再调用买入，单事务能保证失败后不留下新增债务；相较于给所有现货买卖请求增加借款参数，专用入口能保持原现货契约清晰，融资买入也能在个人成交记录中识别。

本期推荐明确输入买入总额和新增借款金额，并展示现金承担的差额。暂不把样稿的“目标账户倍数”滑块接入生产：自动反算借款涉及全账户敞口定义和 AMM 成交后估值，不能用总额乘倍率或现金差额代替。系统名义杠杆以“授信配置”单独展示，成交后风险使用现有权威口径。

## 请求与报价契约

建议新增：

- `POST /api/v1/fx/pairs/{pair_id}/borrow-buy/quote`：已认证、只读融资报价。
- `POST /api/v1/fx/pairs/{pair_id}/borrow-buy`：借款并买入，单次提交。

报价请求：`amount` 为买入总投入（含现有买入手续费），`borrow_amount` 为本次明确同意新增的金圆券本金。两者均为正数，`borrow_amount <= amount`；自有现金投入为 `amount - borrow_amount`，允许为零。金额使用十进制字符串，最多 6 位小数，并校验存储上限及求和后的现金、债务边界。

提交请求在报价请求上增加 `min_out`（最低可接受外币所得）和 `idempotency_key`。无新增借款时继续调用原现货报价与成交接口，不创建零借款流水。

报价返回买入总额、现金投入、新增借款、预计外币所得、手续费、可用现金、现金是否足够、当前授信上限/日利率、预计含息金债、清算净值、风险基数、保证金率、权威风险等级、可执行性及阻塞原因、报价有效期。风险估值不可用时相应值为 null，并禁止融资成交。借款页的 `max_borrow` 只能作为参考，不能当作本次成交后的保证金校验结果。

报价复用统一信贷的交易后估值和准入逻辑，模拟完整买入后的钱包、储备、现金和债务；不写资金、计息、流水或成交。有效期为 30 秒，仅用于前端提示；服务端成交始终按锁内最新储备重报价并执行 `min_out` 保护。输入变化立即废弃旧报价，过期报价需更新。

## 成交与风险约束

最终集成基于主线 7d46d7c，统一信贷为唯一信贷路径；融资入口要求有效风险门槛。新增借款须同时满足 loan_enabled、FX 开市、非 reduce-only、用户协议、非机器人、账户/运营信用未冻结及单币种方向约束。同 pair 有未回补空头时禁止融资建立多头；其他 pair 的持仓、空头欠币和锁金必须纳入全账户判定。

执行步骤沿用现有门闩和事务边界：

1. 发现目标 pair 与全账户抵押、欠币依赖；释放 discovery 事务，再一次取得有序门闩。
2. 目标 pair 使用独占门闩，其余风险组共享；遵守品种行先于 User 行的锁序。锁内重新验证经济版本及依赖完整性，冲突时全部回滚、释放后有限重试。
3. User 锁内查询已有请求结果。查重先于借款、计息写入和新增业务限制；原成功交易的重试即使账户状态后来改变也应返回原成交。
4. 按锁内 AMM 报价和最新可用现金检查现金差额；锁金不能作为现金投入。
5. 将旧本金计息至统一时点 T，再加新增借款本金。模拟 `cash_after = cash_before + borrow_amount - amount`、新钱包余额及成交后储备，执行完整组合准入。新增本金从 T 起息，不能继承旧借款时间被追溯计息。
6. 准入成功后，在同一事务内记录计息/借款、买入、钱包、储备、手续费资金归属、经济版本及审计。不得在这两项之间调用独立会 commit 的接口。
7. commit 前构造并校验成交响应；成功只 commit 一次。commit 后使用已物化成交信息入队发布，不为成功响应额外读取账户全组合。任一明确失败全部回滚。

复用现有授信公式和精度，不提高杠杆，不设单笔独立保证金，也不改变卖出所得优先偿债和回补规则。不可执行的组合、未知回补成本等沿用现有风控拒绝语义。

## 最小数据变更及重试语义

建议在 `FxTrade` 增加可空的 `borrow_amount`（Numeric(16,6)），并将 purpose 约束扩展为允许 `borrow_buy`。旧记录的该字段保持 null；融资记录保存明确请求本金，现金投入从 input_amount 减去本金得到。迁移通过 Alembic，兼容 PostgreSQL 与 SQLite；融资记录要求 side=buy 且 0 < borrow_amount <= input_amount。

沿用 `(user_id, idempotency_key)` 唯一约束。同编号必须匹配 purpose、pair、买入总额、借款本金和 min_out；与现货/开空/回补共用编号命名空间，跨入口冲突返回 409。成功后的重试返回原 trade_id、成交数值和融资拆分，不再次借款、计息或买入。新编号代表新操作。失败回滚的请求不新增持久申请记录。

响应不承诺重放历史账户快照：成交回执返回持久成交数据、融资拆分及 replay 标识；当前账户信息由独立刷新获取。刷新失败要明确提示成交已完成，不把刷新错误当作成交失败。

个人交易 API 展示 purpose 和 borrow_amount；公开成交/SSE 继续只发布现有价格及成交信息，不暴露个人贷款信息。复用借款 LedgerEntry 与现货 fx_trade 审计，必要的成交关联放入现有 reason/payload。审核回放保证先计息、后借款、后买入的用户状态和资金流完整，不能重复计入本金。

迁移回滚遇到融资记录时明确拒绝 downgrade，避免抹掉借款身份或伪装成普通现货；无融资记录时允许恢复旧 schema，保留既有数据。

## 页面配套

在真实 `/fx` 的做多区加入显式融资选项。默认现金买入；开启后展示买入总额、新增借款输入、使用现金、预计所得、费用、日利率、预计含息债务及成交后风险，按钮为“借款并买入”。额度不足、借款关闭、冻结、报价过期和估值不可用均有具体说明；现金差额不自动变成用户同意的借款金额。

沿用当前黑白风格和现有组件，限制改动在做多下单、成交回执和个人记录。授信配置中的名义杠杆不得标成单笔实际杠杆；不把资金显示为已划入独立保证金账户。

融资请求在首个网络写入前按用户持久化到 sessionStorage，保存原 pair、全部参数和编号；未知结果时保留并沿用同编号查询/重试，禁止重新生成编号后直接再下单。复用 FX pending short order 的机制或抽取共用小型工具，覆盖页面重载、组件重挂载和用户切换。存在未知融资请求时禁止新增融资、现货及开空操作，保留核对和恢复入口。存储不可用时禁止融资提交。

成功回执与账户刷新分开；报价、摘要失败时清除旧可提交状态。已有普通现货未知结果处理不在本期扩展为全站幂等项目。

## 实施范围与验收准备

预计改动集中于 FX schema/model/Alembic、FX trading 和融资报价、FX 路由、现有信贷/审计复用点、前端 FX types/API/下单区及文档。普通无债现货路径保持现有查询策略，不默认读取全组合。

### 性能约束（2026-10-10 补充）

设计预期无需新增计算服务或硬件，但实现前不能承诺实际延迟和吞吐。新增开销主要来自融资报价的全组合估值、成交中借款流水及审计写入、风险组门闩等待。复杂账户的持仓品种数量和热门 pair 的并发成交会影响开销；合并事务相较原两次请求减少网络和独立提交，但单次 pair 锁的持有时间可能增长。

- 普通现金报价与无债现货成交不接入融资全组合估值，不额外查借款历史，不增加全站轮询或新后台扫描任务。
- 融资报价沿用输入后 350ms 防抖，只在有效输入变化/主动更新时请求；停留在页面不持续轮询融资风险。不以行情每个 SSE 帧触发全组合融资报价。
- 只读报价不取得写入门闩或 FOR UPDATE 行锁；可用现有版本缓存复用未变动抵押组，实际成交仍在锁内重新验证。
- 每次成交尝试做一次完整增险准入，所需展示估值复用本次结果/快照，不为响应再做独立完整估值；不得简单串联两套独立 handler 造成重复 discovery、User 锁和 commit。
- 请求查重沿用已有唯一索引；一次操作完成后只做必要的一轮账户刷新，避免 quota/summary 的重复刷新。
- 实施后做小范围同机隔离 PG 对照：新融资成交与原“借款再买入”的完整流程比较 SQL、总耗时和 P95；普通现货在融资报价/成交并发下比较吞吐、P95 与锁等待。覆盖简单账户和多品种/含空头账户，记录负载与未覆盖范围。此检查针对具体新增性能风险，不扩展为全站压测。

新增永久测试只填补本功能的资金和请求身份覆盖缺口，优先复用现有 FX、loan、credit 夹具：

- 成功时本金/现金/外币/储备/手续费/审计一致，旧债正确计息，新本金不补收历史利息。
- 滑点、初始保证金、冻结、锁金及同 pair 空头拒绝后，全部资金和成交数据不变。
- 同编号重复与响应丢失重试只产生一笔借款和成交；不同编号独立执行，参数/跨 purpose 冲突拒绝。
- PostgreSQL 并发同编号、不同编号额度竞争、版本变化和实际锁序；迁移的旧数据保留及降级保护。
- 前端未知结果保留原编号，融资拆分提交准确，成交成功后刷新失败不允许误报或重新下单。

实施后运行相关现有后端 FX/loan/credit/audit 检查及前端类型、相关单测、定向 lint 和构建；有 UI 验证时最多截图，不自动点击或填写表单。验收报告记录实际命令、结果和未验证范围。初始准备阶段不执行部署；用户随后明确授权提交推送与自动部署，交付按现有 main CI/CD 执行。
