# 交易请求编号与重试去重：后续待办

日期：2026-10-10。状态：todo，用户明确要求延期；不属于本轮统一信贷优化的实施范围。本文件记录问题和候选方案，不授权数据库或交易接口变更。

## 问题与边界

交易请求超时不代表服务端未执行。同一操作重新发送，可能再次借款、扣款或买卖；剩余额度、余额和持仓检查不能保证后一次失败。

重复请求本身不等于账务失衡。每次成功执行仍须在现有事务内一致更新现金、债务、持仓、池子及审计；借款增加现金时同时增加债务，买卖沿用现有费用和资金来源规则。请求去重解决成交次数与用户意图的一致性，不能替代资金原子性、锁顺序、风控和审计检查，也不证明现有所有路径都无资金错误。

## 当前覆盖

- FX 现货买卖、开空和回补已有 idempotency_key、参数校验和 FxTrade 的 (user_id, idempotency_key) 唯一约束；将来复用和核对现有实现，不重复建设。
- 玩家借款、部分还款及全部还款没有请求去重。
- LMSR 买卖及 writer 的 BuyCmd/SellCmd 没有持久请求编号去重。
- 2026-08-22 审计待办 M11 的 done 表示当时已调整前端超时处理，不表示 LMSR 持久幂等已经实现。

## 待办

- [ ] 明确请求语义：同编号为原操作重试，不同编号为独立操作；同编号不同参数应拒绝。服务端不按时间间隔或相同金额推断是否误点。
- [ ] 明确网页行为：提交中是否合并双击、超时如何沿用编号、如何明确创建下一笔；正常的快速多笔交易不能被误合并。
- [ ] 优先评估复用 LedgerEntry/Transaction/FxTrade，在成功资金流水或成交上保存请求编号及必要原始参数。明确失败并回滚的请求不保存；不默认建立独立贷款申请表或回执表。
- [ ] 明确零资金变动、部分成交、全额还款、参数变更、进程重启、赛季重置及历史流水删除后的保障范围。零操作是否留痕属于后续决策，不作为本轮依赖。
- [ ] 对照按唯一索引查询、合并已有 SQL、唯一约束冲突后再查旧结果三种路径。验证实际执行顺序、事务回滚和旧结果返回，不能只加编号字段或仅依赖前端按钮。
- [ ] 在同机同负载下测量数据库 round trip、writer 排队、吞吐和 P95/P99；FX 现有路径与 LMSR 高频路径分别评估。不默认每笔额外查询完整交易历史，不引入新的通用订单系统或缓存服务。
- [ ] 在可丢弃 PostgreSQL 测试库验证并发同编号、响应丢失重试、两笔不同编号、同编号参数冲突与资金/持仓/审计一致性；沿用现有交易锁序与 writer 提交后内存更新规则。

## 本轮处理

本轮只保留提交后的结果与额度刷新解耦、冻结提示、估值复用、风险等级一致、扫描统计和文档修复。贷款请求编号、流水字段扩展、去重迁移、客户端重放和全站买卖推广均留到本待办启动后再讨论实施。
