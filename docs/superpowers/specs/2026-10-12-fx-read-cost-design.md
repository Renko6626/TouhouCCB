# FX 报价与交易读取精简设计

状态：第一阶段 Tasks 0–4 完成，最终 medium 审阅 spec/quality PASS、整体 Ready；隔离工作树交付，未 commit/push/deploy。root 已关闭本任务临时 PG。用户已明确确认取消全体玩家合计借币本金上限，保留开空和真实库存检查。基线为 `feat/fx-net-trading` 的 `29c1250`。本文“旧 FX”指当前统一多空系统，“新 FX”指本次优化候选。

## 目的与推荐范围

先减少数据库往返。第一阶段合并报价基础读取和交易请求查重，并执行已确认的合计借币上限停用。除这一明确业务变更外，报价和成交含义保持；不改 AMM、账户模型、接口字段、请求时机、资金检查或个人风险边界。

第二阶段候选是复用交易锁内已有输入，降低完整依赖重新发现的成本。这涉及内部一致性边界，须另行确认并证明安全。前端预览作为可选产品方案，不能自动纳入第一阶段。

## 服务分层与复用边界

现有代码已经复用 AMM 与真实成交记账，不为优化创建第二套交易算法或账务服务：

| 层次 | 当前职责 | 本次处理 |
| --- | --- | --- |
| `fx/amm.py` | 买入、卖出、精确回补的 Decimal 定价和手续费舍入 | 原函数保持 |
| `net_trading._simulate` | 报价与执行共用的分腿、资金后态和准入模拟；必要时调用共享风险服务 | 只改变其输入取得方式，除上限停用外保留判断 |
| `trading._write_spot_ledger` | 现货扣款/收入、钱包成本、储备、手续费、成交及审计，卖出按原规则还债 | 统一入口、旧现货入口及融资入口继续复用 |
| `shorts._write_open_ledger` | 实际借币、卖出、欠币/锁金、手续费、成交及审计 | 新旧开空继续复用 |
| `shorts._write_cover_ledger` | 实际回补、先息后本、锁金释放、手续费、成交及审计 | 统一入口、旧回补和强平继续复用 |
| net / 旧入口外层编排 | 锁与依赖、请求身份、利息时点、账务函数调用、整笔提交与发布 | 第一阶段仅合并 net 查重，不重写各入口 |

下层账务函数可以 flush，但不替调用者 commit。统一交易必须在一笔事务内按顺序调用一至两条账务腿，第二腿使用第一腿后储备，最终一起提交或回滚。不能改为连续调用两个各自提交的旧 HTTP/service 外层入口。

净交易模拟和旧入口的准入编排仍存在各自逻辑；它们输入单位、回补方式及风险后态不同。本次不把所有判断强行合并成一个大函数，也不调整强平对失败/回滚的边界。优先优化已经定位的读取成本。

## 证据与收益口径

隔离 SQLite 的真实 HTTP 固定样本计数包含认证；冷/热仅指配置缓存。Task 1 普通 cash 报价冷 8→5、热 6→3，mixed_debt（FX 金债加正 LMSR 仓）冷 21→18、热 18→15，报价 DML 均为 0。这些是指定样本实测值，不能推广为所有账户的固定成本。

Task 2 cash 成交冷 10→9、热 8→7，DML 8 不变。cross_sell 从原基线到 Task 3：报价冷 21→17、热 16→12（基础读取减少 3、上限 SUM 减少 1）；成交冷 32→29、热 28→25（首次和重试的查重各减少 1、上限 SUM 减少 1），DML 14 不变。完整依赖发现及权威利率/风险查询保留。

记录包含独立 PG 并发组实际通过的证据，但未测 PG EXPLAIN、生产耗时或吞吐；减少 SELECT 不等于证明更快。固定初态、其他样本、检查命令及阶段限制见 [验证记录](../../fx-read-cost-validation-2026-10-12.md)。旧基线不能证明当时未读取 dotenv；后续临时 harness 已禁用 dotenv 源并校验独立 SQLite URL。

## 第一阶段：读取相同内容，减少往返

### 报价基础读取

在 `backend/app/services/fx/net_trading.py` 添加内部只读加载器。以目标 FxPair 为主表，一次 SELECT 读取 User、目标 FxWallet 和 FxTreasury；关联使用外连接并限定用户、品种，避免无钱包或无金库时丢失品种。唯一约束保证正常结果至多一条，不将全部短仓加入该查询造成行乘法。

`quote_net_trade(db, user_id, pair_id, req)` 与 HTTP 请求/响应签名保持原样。先保留不存在品种的 404，再保留不存在 User 的原错误行为；缺钱包和缺金库仍为 None。继续使用与当前普通 SELECT 相同的 ORM identity-map 语义，不隐式增加 populate_existing 或把交易权威读取改为认证对象复用。

全部本人短仓仍单独读取，包括其他品种的欠币和锁金。模拟仍得到真实金库余额，保留库存、手续费入库、数值上限、非有限值、异常双方向、资金和状态检查。

自然语言流程：认证 → 一次读取账户、品种、钱包和金库 → 读取全部本人短仓 → 原模拟和风险检查 → 原报价。

不实施无债跳过利率读取：它通常只省冷配置的一次查询，却涉及异常配置处理差异。也不省略金库读取：普通现货手续费仍可能令金库越界。

### 成交请求查重

在已持有 User 锁的原位置，将 FxExecution 完整回执查询和 FxTrade 旧编号存在性查询合成一次 SELECT。使用常量单行来源、外连接回执与旧编号 EXISTS，保证没有回执时仍能返回旧编号标记。

保留回执优先级、规范参数比较、原回执重放、旧编号冲突、先重放后检查经济版本的顺序，以及重放的 rollback 行为。不得将两个编号空间合并成存储迁移，也不得把查重移到 User 锁外。

所有交易锁序、锁外依赖发现、锁内完整重发现、利息结算、权威风控、分腿账务、一次提交和提交后发布保持现状。

### 已确认：停用合计借币本金上限

用户已确认只取消所有玩家合计借币本金上限，保留开空功能、金库实际外币余额检查和个人风控。新开空不再汇总该品种所有玩家尚未归还的本金，也不与旧上限比较。

覆盖 `shorts.py` 的旧开空执行、旧开空报价和 `net_trading.py` 的新开空模拟三个入口；新旧 API 都应遵守同一业务规则。删除无剩余调用的合计本金查询 helper。已有上限为 0 或小于本次借币数量，不再单独阻止开空；库存不足、冻结、关闭开空、只减仓、滑点和个人风险仍会拒绝。

不为停用新增迁移：旧数据库列及管理员 API 字段保留兼容，在文档中注明不再生效；旧值不会被清空，也不会作为停止开空的替代开关。管理页面移除该可编辑设置，避免给管理员错误预期。继续通过现有全局开空开关或品种状态控制开空。

该业务变更需要调整原来验证上限拒绝的用例，改为验证在库存和风险允许时旧上限不阻止开空；保留真实库存不足、并发库存不超借和风险拒绝的有效断言。前端旧错误解析若供历史响应兼容使用，可保留，不因停用扩成无关清理。

原合计上限为 0 曾能间接阻止开空，停用后必须使用现有开空开关/品种状态控制，不能继续向管理员展示“0 禁止新增”。上线说明需指出这一行为变化；本次不访问生产库盘点旧值、不自动部署。

## 后续交易候选：复用锁定输入，继续发现完整组合

当前有债或欠币交易先尝试目标品种锁，发现需要组合门闩后回滚；锁外发现后重试，锁定目标品种、User、目标钱包和全部本人短仓，再做一遍完整依赖发现。

候选方案是为内部依赖加载增加“复用已锁 User 和全部短仓”的入口：正 LMSR 持仓、其他 FX 钱包、所有相关品种的价格/状态/费用仍新读；短仓本金、利息和锁金来自锁定行，短仓所属品种的行情元数据仍新读。返回相同 DependencySet，复查完整门闩覆盖及经济版本。

权威风控的即时利率、用户刷新、持久欠币集合、最新组合行情、过期模拟保护和有限重试均保留。不能直接删除第二次发现、用报价阶段快照替代，也不能只用账户版本代替行情刷新。

同组合样本的第二次发现有望减少约 2 次读取，但需要覆盖 LMSR-only、FX-only、混合持仓、只有短债和其他品种义务，不能承诺所有组合固定减少 2 次。本阶段须先确认内部风险边界方案，第一阶段不实施。

## 前端可以承担的工作与选择

LMSR 当前输入报价为本地价格预览，资金和信用校验留到下单。FX net 报价还返回分腿和账户可执行性，因此两者职责不同。

FX 当前公开 snapshot/SSE 不提供池子储备与精确费率；只有边际价和参考买卖价。认证报价的腿虽返回储备，但已量化的手续费不能反推准确费率，旧储备也会过期。现有公开参数不足以完整复制任意数量的滑点、手续费与跨零模拟。

第一阶段继续输入停 350ms 后取得权威报价，不新增前端 UI 或公开参数。

可选方案 A：输入立即用公开参考价做粗估和方向提示，明确未包含完整数量滑点；仍在 350ms 后请求权威报价。它改善感知响应，但不减少服务器请求数量。前端不得用粗估授权交易、生成正式滑点底线或确认增仓。

可选方案 B：延长停输入等待，或点击交易时先获取权威报价再确认。它可减少请求，但改变等待和确认流程，须用户选择。

精确本地 AMM 预览需要另行确认储备/费率接口的可见范围和时效规则，属于重要接口与信息暴露决策，本设计不扩展公开字段。

## 不变量与验证边界

- 保留原 AMM、六位金额、Decimal 字符串、手续费舍入、利息和保证金公式。
- 反向先平仓，跨零后段失败全回滚；增仓许可、经济版本及滑点底线保持。
- 所有本人短仓义务与锁金保留，不能通过目标品种局部数据假定无债。
- 品种先于 User 的锁序、完整门闩集合、等待释放连接和有限重试保持。
- 回执与旧编号空间、未知成交恢复、一次提交、真实腿审计/行情保持。
- 不更改 schema、公共响应、调度器、部署组件；限价单后置，不读生产库或运行生产压测。
- 复用相关已有检查；新增永久测试仅填具体行为缺口，不用 SQL 结构字符串断言固定实现。

实施验证使用隔离小数据库对真实 HTTP 和服务路径计数，分别记录 SELECT 与 DML、冷热配置、账户组合。请求计数仅作诊断产物，不宣称生产容量。交易阶段若调整依赖复用，另需隔离 PostgreSQL 并发与相应失效风险验证。

取消总量上限后，库存成为唯一品种总量约束：在现有 PG 层新增一个具体覆盖缺口，两个不同用户经 net/旧开空入口竞争同一品种、库存仅够一笔时，只有一笔成功，另一笔库存不足且无账务副作用。保留真实 gate/事务/行锁，使用零手续费便于独立断言库存和本金守恒，不加源码结构或内部调用次数断言。

前后采样固定同一 UTC 模拟时点和初始经济状态，避免含息债随采样耗时不同导致假差异。字段对比保留全部财务/分腿/拒绝原因；单独剔除运行编号、数据库自增 ID、过期/生成时间。上限停用预期改变的场景单独断言新规则，不能要求新旧可执行性完全相同，也不能放宽其他字段掩盖问题。
