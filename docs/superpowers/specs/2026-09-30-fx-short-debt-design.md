# FX 做空与统一债务风控设计

创建：2026-09-30。状态：设计草案，待用户审阅；本次完成现有代码检查与数学核对，未实现做空业务代码。

本设计扩展 [统一贷款与固定强平设计](2026-09-29-unified-credit-risk-design.md) 的多头范围。既有金圆券贷款继续保留；新增真实外币回补义务，统一计算账户权益、额度和强平。活动背景见 [一周参数草案](../../fx-week-activity-config.md)，其中 20 倍等数值是活动候选，不能当作本更新已批准或已上线的配置。

## 1. 产品目标与边界

用户已确定需要空头：利好与利空都应提供交易机会，借入外币卖出应真实影响当前 FX AMM，并能在上涨时触发回补强平。原有 LMSR、FX 多头、金圆券贷款、兑换和管理员操作的账务必须一起检查，不能只增加一个卖出按钮。

本稿选择真实借币现货空头：从该 pair 的系统 treasury 借外币，立即卖入同一个 AMM，回补时买足欠币归还 treasury。相比仅按价格差结算的合约，资金与币的来源明确、订单真实推动池价，并复用现有成交与行情。代价是必须新增外币债务及买入方向的强平执行。

首版规则：

- 一个账户现金余额、一笔原有金圆券贷款；按 pair 记录必要的外币回补义务，不增加用户主动选择的贷款来源或独立账户。
- 一个名义杠杆上限、一种贷款日利率、一组初始与维持门槛，LMSR、FX 多头和空头共享权益。
- 建议首轮运营上限 10 倍、普通参与以 3–5 倍为主；20 倍保留为后续运营选项。本稿不自动更改现有杠杆参数。
- 同一用户同一 pair 首版只允许一个方向：有现货外币时先卖完才能开空；有欠币时普通买入不能新建多头，须走回补入口。不同 pair 可分别做多、做空。
- 空头卖出所得计入总现金但锁定用途，不能消费、转走、偿还其他贷款或支撑另一份独立额度。
- 继续使用定时扫描、固定批次、每用户每轮一个资产组；不引入 [延期的事件触发强平](2026-09-30-event-driven-liquidation-deferred.md)。
- 不增加永续、资金费率、用户出借外币、保险基金、净敞口抵消优惠、最优清算搜索或全站经济锁。

旧稿“所有负债只有一笔金圆券金额”的适用范围到现货多头为止。外币负债必须保存数量并随回补成本变化；不能将开仓时的金圆券折算金额塞入 `User.debt`，也不能用负数 `FxWallet` 同时充当资产和负债。

## 3. 金额、现金与数据权威

### 3.1 保留权威并新增空头表

- `User.cash`：账户拥有的全部实际金圆券，包含空头卖出所得。金额始终非负。
- `User.debt`、`debt_last_accrued_at`：仅原有金圆券债务与其结息时点，语义不变。
- `FxWallet`：仅用户实际拥有的外币，继续按非负现货处理。
- 新增 `FxShortPosition`：每个 `(user_id,pair_id)` 一行，保存外币本金、利息与空头现金用途。

建议字段：

| 字段 | 含义 |
| --- | --- |
| `id`、`user_id`、`pair_id` | 稳定标识与唯一用户/pair 约束 |
| `principal_foreign` | 尚未归还的外币本金 |
| `interest_foreign` | 已落库但未归还的外币利息 |
| `interest_last_accrued_at` | 与现有计息规则一致的时间基准 |
| `restricted_gold` | 已包含在 `User.cash` 中、专用于本空头回补的金圆券 |
| `proceeds_basis_gold` | 剩余开仓净所得的收益计算基准；不作为额外现金或授信资产 |
| `created_at`、`updated_at` | 审计及状态展示时间 |

本金、利息、锁定额、收益基准均为非负六位 Decimal，模型和数据库均有约束。外币债务字段采用 `Numeric(24,6)`，回补输入与储备写入仍须验证现有存储上限；溢出不得截断债务或当作零。活跃欠币有明确结息时点，空仓则时点为空，SQLite 读回的 naive 时间按 UTC 解释。`FxWallet` 补齐非负约束，预检发现负钱包须中止迁移并修复，不能将其自动转换成空头。

空头行可在平仓后保留：本金、利息、锁定额、收益基准全部归零，计息时点清空。成交历史由 `FxTrade` 与审计保存，不删除来实现“平仓”。普通请求不得写出只归零欠币而锁金仍非零的状态。

### 3.2 现金的三种含义

记总现金为 C，各空头锁定额合计为 S：

```text
账面总现金 C = User.cash
锁定现金 S = Σ restricted_gold
未被用途锁定的现金 F_cash = C − S
```

始终要求 `0 <= S <= C`。S 是 C 的子集，估值不能再把 `C+S` 相加。

`F_cash` 不等于可随意消费的金额：其中还可能承担保证金。消费/转出先满足现金用途边界，再满足交易后风险检查；兑换与弹幕沿用更严格的有债禁消费规则，扩展为有金债或欠币均禁止。

保留一笔现金权威，不新增一个可独立充值提现的空头账户。锁定额与收益基准需要分开：亏损强平可能额外消耗本仓锁金，不能因此篡改开仓成本、制造已实现利润。

## 4. 外币来源、容量与利息

外币来源为 `FxTreasury.foreign_balance`，不是凭空生成，也不是直接把池子外币记作用户借款。该字段继续代表可支用的实际库存，不含贷款应收。

新增 pair 级 `short_lending_limit_foreign`，默认 0 表示不开空。开空时在 pair 与 treasury 锁内同时要求：

```text
申请借币 Q <= treasury.foreign_balance
Σ 此 pair 的未还外币本金 + Q <= short_lending_limit_foreign
```

本金额度不限制正常产生的利息。总本金求和可在 pair 锁下用索引聚合；首版 50–100 人不另维护第二份可漂移的总债务余额。调低上限只停止新借，不免除存量欠币；归还会补回 treasury 实际库存。

共用 `loan_daily_rate`，按各自欠款币种计息：金债产生金债利息，外币债务产生同币种利息。外币计息不再向 `User.debt` 收一份重复费用。

```text
Q_effective = quantize_6((principal_foreign + interest_foreign)
                        × (1+r)^(elapsed_seconds/86400))
新增外币利息 = Q_effective − 当前已存外币总债务
```

复用现有日复利计算与六位量化语义、统一 UTC 时点 T；不足一单位的利息不无故推进旧本金的时间基准。追加本金前先结旧债，到 T 新增本金；不能给新借币追收过去的利息。归还先冲利息、再冲本金。

定时结息扩大候选用户集合，仍可使用现有最短结息间隔；风险读取永远含未落库利息，不依赖 sweep 是否已写库。纯结息只改变债务与用户经济版本，不改变池储备或 treasury 实际库存。

日利率修改采用停写维护：在旧率下将全部金债和外币债务结到同一个 T，记录审计并完成事务，再修改利率与重启；任何失败都不能半数旧率、半数新率或追溯改价。首版不支持运行期间热切换利率。

## 5. 空头回补数学与两种净值

### 5.1 买足指定数量的报价

现有 `quote_buy` 是输入指定金圆券、输出外币；回补需要指定欠币数量 q、计算包含买入费率 f 的总金圆券输入。新增纯数学 `quote_buy_exact_out`，不在用户事务内搜索最大可开数量。

池金储备 G、外币储备 F，q 为六位正数，必须满足 `q < F`：

```text
所需净金输入 n_raw = G × q / (F − q)
n = ceil_6(n_raw)
总金输入 X = ceil_6(n / (1 − buy_fee_rate))
金手续费 fee = ceil_6(X × buy_fee_rate)
池子更新：G_after = G + X − fee；F_after = F − q
```

两次向上量化保证按现有向上收手续费后仍能买足 q。报价以足够的 Decimal 中间精度计算，验证有限值、存储范围、费用小于输入、储备为正和 `G_after*F_after >= G*F`。外币输出恰好为 q，不将普通 exact-input 报价多出来的外币丢弃、铸币或偷偷建立多头。

q 接近 F 时成本急剧增加，q 大于等于 F 时无法完整报价。不能使用 `q*边际价`、一单位 ask 乘数量或输出向下舍入的普通买单来代替全仓回补成本。

### 5.2 展示与风控

记 A 为所有正资产的实际整组净清算回收，K 为所有空头的实际整组回补成本，D 为含息金债：

```text
展示净值 = C + 正资产边际市值 − D − Σ(Q_effective × 当前边际价)
风控净值 E = C + A − D − K
K = Σ quote_buy_exact_out(各 pair 的全部 Q_effective).gold_input
```

每个空头 pair 聚合报价一次，包含该 pair 买入费率。不同 pair 的 K 相加，不把摩拉和龙门币的数量相加。首版不允许同 pair 自持现货与欠币，避免在同一初始储备上把两条可逆腿独立估值、漏掉执行先后。

负债无法完整报价时，返回明确的 `risk_status=blocked`、可空的风险净值/基数和原因；不得令 `K=0`，不得使用 Infinity/NaN 进入金额字段。显示仍可给有来源的边际估值，但明确其不是可执行回补价。

若数学报价有限但市场被全停，K 可以作为参考成本保存，可执行性仍是 false，增险拒绝。读模型必须分开“未知回补成本”和“已知报价但无法执行”，不能沿用正资产的不可执行则值为零规则。

## 6. 统一杠杆与风险基数

### 6.1 为什么不能直接用 D+K

多头的 L 倍名义仓位由 `(L−1)E` 金债与 E 本金共同组成；空头的 L 倍仓位对应 L×E 的欠币回补敞口。直接把 D+K 放进旧 `E/D` 会把空头上限压成 L−1 倍，也无法正确覆盖已用自有资金持有的跨品种多头。

本稿保留已有配置与门槛的数值含义，使用一个扩展风险基数 B：

```text
L = credit_leverage；α = (L−1)/L
I = 1/(L−1)；m = credit_maintenance_ratio

B = max(D, α×A) + α×K

新增风险允许：E >= I×B
有金债或欠币时强平触发：E < m×B
已有 run 恢复：所有负债归零，或 E >= I×B
```

`max(D,αA)` 避免把借钱买入的同一多头在债务与资产敞口中重复计数；同时将自有资金买入的正资产纳入与空头共享的总敞口。K 增加共享风险占用，不按多空方向抵消。

B 是风险基数，**不是债务余额**。真实负债仍是 D 与每币种欠币数量；不能把 B 写回 `User.debt`，也不能把新 `E/B` 填进旧 `equity_to_debt` 字段。

为避免除法边界截断后放宽准入，执行比较使用：

```text
W = max(L×D, (L−1)×A) + (L−1)×K
准入：L×(L−1)×E >= W
触发：L×E < m×W
```

仅展示时计算 B=W/L 和保证金率，展示金额向保守方向量化，不使用截断后的展示率决定成交。

### 6.2 兼容性证明与共享示例

无空头时 K=0、C>=0、E=C+A−D：

- 旧准入成立时 `D <= (L−1)E`，且 `A <= E+D <= LE`，因此新的两部分准入均成立；反向也成立。无债现货快路径可保持。
- 若旧强平触发，E 小于 mD 且 m<I，得到 αA<D，故 B=D。若 αA 占主导，则 E 已高于初始门槛，不会凭资产项引入旧规则没有的强平。
- 所以无空头账户的准入、维持与恢复判断保持等价。新保证金率展示数值在非临界健康状态可能不同，必须用新字段并说明基数。

理想化例子（忽略手续费、滑点和利息，上限 L=10）：

| 状态 | C | A | D | K | E | B | 准入 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 500 本金的 10 倍多头 | 0 | 5000 | 4500 | 0 | 500 | 4500 | 边界允许 |
| 500 本金的 10 倍空头 | 5500 | 0 | 0 | 5000 | 500 | 4500 | 边界允许 |
| 同本金各开满 10 倍多与空 | 5000 | 5000 | 4500 | 5000 | 500 | 9000 | 拒绝 |
| 5 倍多头与 5 倍空头 | 2500 | 2500 | 2000 | 2500 | 500 | 4500 | 边界允许 |
| 开满空头后再申请 4500 金现金贷款 | 10000 | 0 | 4500 | 5000 | 500 | 9000 | 拒绝 |
| 自有资金现货 500，再开空 4500 | 4500 | 500 | 0 | 4500 | 500 | 4500 | 边界允许 |

“空头现金 5500”包含 5000 锁定所得，不表示可以拿 5500 去消费。实际边界订单还要扣手续费并以真实交易后报价复检，不保证恰好满倍成交。

### 6.3 借款、消费与交易

现有订单先结息、模拟现金/持仓/欠币/池状态，再计算完整组合的 E、A、K、B。不能只检查这一个 pair，也不能因为金债为零而跳过。

在当前准入已满足时，现金借款理论上限为：

```text
max_new_gold_loan = max(0, (L−1)×E − D − α×K)
```

向下量化、锁后复检；当前已经低于初始门槛或有未知负债报价时返回零。可借现金不是可开仓数量或可消费额度：新买入还会增加 A，必须另做交易后检查。

无新增资产的普通现金扣款同时满足 `金额<=F_cash` 与扣款后的初始门槛；现有有债禁止兑换更严格，继续执行。管理强制借款/扣款若明确允许例外，仍不能写出 C<S 或忽略外币债务，且要冻结新增信用并记原因。

纯回补、纯卖出、充值和有效还款可在低于初始门槛或增险冻结时执行。仅有金债才能进行金圆券还债；不能用“还款金额”悄悄转换外币义务。卖出/回补收益再开仓是另一个增险请求。

## 7. 开空、回补与锁金事务

### 7.1 开空或追加空头

用户提交六位外币数量 Q 和 `min_gold_out`，不用预先申请一笔金圆券贷款：

1. 校验总交易闸、贷款闸、开空闸、pair 状态、TOS、非 bot、冻结状态和同 pair 无现货。
2. 发现完整组合依赖、获取门闩与行锁，统一时点结金债及相关外币利息。
3. 验证 treasury 库存及本金额度；模拟从 treasury 借 Q，按现有 `quote_sell` 卖出 Q。
4. treasury 外币扣 Q，池子接收扣外币手续费后的净输入；手续费回 treasury，用户 cash 增加净金所得 P。
5. 本仓本金加 Q；`restricted_gold += P`、`proceeds_basis_gold += P`。已有锁金不释放，不把开空所得自动还金债。
6. 使用交易后池子、含新借币的完整负债报价验证共享初始门槛；未通过全部回滚。
7. 同事务保存成交、审计、用户经济版本和 pool_version，提交后发公开价格帧。

不得出现借币已记、卖出失败；不能把申请 Q 直接加进可自由卖出的 `FxWallet`，让用户分两次请求绕过保证金。

### 7.2 普通指定数量回补

请求 q<=本仓 Q_effective，带 `max_gold_in`；不存在空头时拒绝，不变成普通买入。另支持与固定数量互斥的 `cover_all=true`：锁内结息后取当前全部欠币作为 q，再验证价格上限，避免报价至成交之间的新利息留下小额残仓。幂等身份保存“全回补”请求及实际执行量，重试不能关闭后来重新开的仓位。

1. 结息并用 exact-output 报价算真实成本 X，验证用户价格上限。
2. 基础锁金释放 `S_base=floor_6(S_position×q/Q_effective)`；完整平仓释放全部剩余 S，消除舍入尾差。
3. 若 X 不超过 `F_cash + S_base`，采用比例释放。若纯减债回补需要更多本仓担保金、但 X 不超过 `F_cash+S_position`，允许释放 `max(S_base,X−F_cash)` 来支付本次回补。不得触碰其他空头锁金。
4. 用户现金扣 X，净金输入进 AMM，买入手续费进 treasury，AMM 恰好输出 q 并归还 treasury；不进入用户现货钱包。
5. q 先冲外币利息、再冲本金。锁金按实际释放额减少；收益基准独立按 `floor_6(proceeds_basis_gold×q/Q_effective)` 分摊，完整平仓结清全部尾差。
6. 本笔已实现结果为分摊收益基准减真实 X；不得用消耗了多少锁金代替收益基准。
7. 更新所有后态、版本和审计；完整平仓归零本仓金额与计息时点。释放后的现金仍要按正常风险规则才能消费或重新开仓。

普通指定数量回补资金不够则明确拒绝，不私自借新金债，不静默部分成交。用户可选择更小数量或充值；自动强平的资金受限处理见下一节。

### 7.3 守恒与退款

除独立的原有发行/注资/借金圆券操作外，开空与回补各自满足：

```text
金圆券实际存量：pool_gold + treasury_gold + Σ user.cash
外币实际存量：pool_foreign + treasury_foreign + Σ wallet.foreign_amount
```

借币本金和利息是应收/应付，不是另一份已经存在的外币，不加进上述实物总量。开空借 Q 后 treasury 减 Q、用户欠 Q；回补归还本金或利息时 treasury 才增加实际收到的币。

零费用、无舍入且无中间订单时开空再全回补可逆；有手续费/舍入时不能产生用户无风险正收益。任何拒绝、异常或重试不得留下钱/币/债/锁金单边变化。

## 8. 固定强平与坏账

扫描候选扩展为：金债>0，或任一空头本金/利息>0，或已有活跃 run。继续稳定分页覆盖全部候选、至多三个 worker、扫描轮次不重叠，不按每次价格变化同步展开所有用户。

新 run 按共享维持门槛触发，活跃 run 按共享初始门槛恢复。仍然每账户每次扫描至多一个组动作：

1. 可先用未被锁定的现金偿还金债；绝不动空头 S。结息与还债后重新估值，达到恢复目标结束。
2. 正资产组的排序金额为整组净回收 A_group；空头组为整组回补成本 K_group，按绝对金额降序、同额按 `(product,id)`。不是将负数 K 填入现有正回收过滤器。
3. E>0 时处理选中组的配置比例，向上量化数量并封顶；E<=0 时计划关闭选中组全部。
4. 多头仍卖出并用未锁现金按原规则还金债；空头使用本仓锁金与未锁现金买币归还，允许前节的额外本仓锁金消费。
5. 计划回补成本超过可付现金时，系统可使用不超过 `F_cash+S_position` 的金输入执行预算受限 `quote_buy`，实际输出封顶计划欠币量；若足以完成计划量则改用 exact-output。按实际归还量和真实成本更新锁金/收益基准，记录 `limited_by_cash`，不能把部分结果标成已全平。
6. 金额与数量太小无法成交则记录阻塞，不制造免费回补。涉及债币价格未知时，冻结增险，只尝试能够独立证明资金覆盖且实际减少欠币的回补；不使用未知 K 去承诺已恢复。
7. 每批事务提交后重估、更新 run，未恢复留待下一轮。不增加成交后即时清算循环或最优关闭搜索。

外币义务不属于“没有正持仓就可以结束 run”：即使钱包/现金已空，欠币仍存在。可用资金耗尽而债务残留时保留本金和利息，标记资不抵债并冻结新增信用；仅报价/市场状态阻塞且尚可恢复时保留阻塞原因与后续扫描续接。

后续充值可用于归还剩余外币义务。管理员核销必须是显式、按币种数量的独立操作，记录本金、利息与原因；减少应收而不向 treasury 铸造已损失的币。首版只支持完整核销选定 pair 的剩余义务，归零本金/利息/收益基准并释放该仓锁金，用户 cash 不因此增加；记录收益基准的核销调整，不能把行政免债包装成交易盈利。金圆券免债不自动核销外币，核销后是否恢复授信仍是另一动作。

## 9. 状态与配置

新增全站 `fx_short_enabled=false`，只控制开空/加空；降低该闸不删除欠币，也不阻止正常允许的回补和强平。pair 的本金借出上限默认零。

| 条件 | 普通买现货 | 卖现货 | 开空/加空 | 回补 |
| --- | --- | --- | --- | --- |
| trading，非 reduce_only | 允许原有检查 | 允许 | 全部贷款与风控闸通过才允许 | 允许 |
| trading/paused，reduce_only=true | 禁止 | 允许 | 禁止 | 允许 |
| paused，reduce_only=false | 禁止 | 禁止 | 禁止 | 禁止用户成交，标记无法执行 |
| closed/draft/archived | 禁止 | 禁止 | 禁止 | 不应有存量空头；异常存量保留义务并阻塞 |

回补在 AMM 是 buy，但风险上是减仓；现有仅按 side=buy/sell 的判断必须改为动作目的。总 `fx_enabled=false` 沿用用户交易全停语义，系统强平仍走自己的闸；关闭开空闸或贷款闸不关闭已允许交易市场中的回补。

普通关闭、归档、删除 pair 都必须检查含息欠币与锁金，非零则拒绝。运营暂停优先 reduce_only；紧急全停须明确其会阻塞回补并保留审计。不能通过状态变更让负债消失。

增险冻结作用于借现金、开空、加空和其他增险买入；现金充值、还债、回补与按规定减仓保留。已有坏账不能凭金债归零就自动解冻。

## 10. API、展示与历史兼容

建议独立玩家入口，保持现有 spot 请求语义：

| 路径 | 请求核心 | 行为 |
| --- | --- | --- |
| `POST /fx/pairs/{id}/short/quote` | `action=open/cover`、`foreign_amount` 或回补专用 `cover_all` | 返回报价、现金用途与模拟风险；有短有效期 |
| `POST /fx/pairs/{id}/short/open` | `foreign_amount`、`min_gold_out`、`idempotency_key` | 原子借币卖出并锁金 |
| `POST /fx/pairs/{id}/short/cover` | `foreign_amount` 或 `cover_all`、`max_gold_in`、`idempotency_key` | 指定数量或全部买回归还 |
| `GET /fx/pairs/{id}/short` | 当前用户 | 欠币、本金/利息、锁定额、收益基准、参考回补成本 |

以上路径挂在现有 `/api/v1` 下。新入口的钱/币字段用十进制字符串，数量和价格不得经前端 Number 重新拼接成交输入。既有字段保持原有 JSON 类型，新读字段逐项适配，不借此整体改变旧 API 的序列化。开户数量/杠杆选择是报价辅助，后端以指定订单的交易后组合决定接受，不搜索并承诺最大可开仓量。

`FxTrade.side` 保留 underlying buy/sell，新增 `purpose`（默认 spot，short_open、short_cover）和持久化请求身份所需的指定数量/最大金输入等字段。强平 source 沿用 liquidation，目的为 short_cover；公开行情仍只显示真实成交价，不泄露系统干预来源或其他用户负债。

账户概览新增 `available_cash`、`restricted_cash`、`short_positions`、外币总回补成本、`risk_basis`、`equity_to_risk_basis`、风险版本与 blocked 原因。`cash` 仍表示总实际现金，`debt`/`debt_with_interest`/`equity_to_debt` 仍只表示金债；新字段不能伪装成兼容债务投影。

资产页、贷款页、账户头部、称号、排行榜和财富统计使用相同展示净值定义，扣除外币义务，不能把空头卖出所得展示为新赚本金。交易页分别显示买入/卖出与开空/回补，说明共同抵押、锁金和上涨强平；不能将“卖出持有资产”按钮静默变成开空。

展示空头净所得基准、实际回补成本及其差额；不将利息增长后的锁金/欠币比伪装成历史开仓均价。历史字段分开还金债金额、归还外币数量、买币支出与手续费币种。

## 11. 服务边界、并发与幂等

建议最小模块分工：

- `fx/amm.py`：exact-output 数学，不查库、不写账。
- 新 `fx/shorts.py`：开空/回补事务内执行、欠币结息、库存与锁金，不自行 commit/SSE。
- `credit/risk.py`、`valuation.py`：完整依赖、A/K/E/B、准入及读取，不能复制两套风险模型。
- `credit/execution.py`、`sweep.py`：定时固定强平编排，委托方向正确的 FX 执行器。
- 统一现金服务边界：所有扣款和还金债先区分总现金与锁金；借款依赖已有借贷账本。
- 审计/读模型：保存并重放新权威状态，展示不参与资金决定。

沿用 OWNERSHIP 单写守卫、品种门闩和稳定锁序：

```text
锁外发现全部正持仓与空头 pair、用户经济版本
→ 目标价格变化组独占、其余依赖共享，按 GroupKey 全序取 GATES
→ 数据库 pair 行锁（需要时）→ User → 钱包/空头行（pair_id 升序）→ treasury
→ 重验版本与持仓集合，统一结息，重新报价及准入
→ 原子写入与 commit
→ 释放门闩后异步发布行情
```

外币利息只改本用户债务时可使用 User 与自身空头行锁，不在持 User 锁后补取更早的 pair/GATES。任何需要价格判断或库存变更的路径都必须先取完整门闩。LMSR consumer 内取门闩，入队及等待不得持连接或用户锁。

无金债不再等于无风险：无债快路径仅在没有金债、欠币和本次新增杠杆风险时成立。锁内用索引确认外币义务，不依赖可漂移的内存标记。若并发发现新增空头则退出并重新发现完整依赖，有限重试，不持锁补拿遗漏品种。

FX 快照/版本必须纳入买、卖两侧费率及状态；缓存只缓存有完整版本的组报价，外币含息数量也属于报价输入，不能缓存一份不随时间变化的 K。批量读取空头行，不逐用户逐 pair 查询公共行情。

复用 `(user_id,idempotency_key)` 成交唯一约束，身份包含 purpose、pair、指定数量和 min/max 条件；现货与空头同 key 必须判冲突。重试返回保存的成交及审计后态，不因当前已平仓再次借币。强平继续用 `(run_id,round_no)` 幂等。

## 12. 审计、强平记录与全站资金入口

每笔开空/回补保存完整审计包：

- 用户 cash、金债及锁金总额前后；外币本金、利息、收益基准与时点前后。
- treasury、池储备、费用、借出/归还数量、实际金收支、数量请求与价格限制。
- 动作目的、用户经济版本、pool_version、同一操作键及来源。
- 回补分摊收益基准、实际释放锁金、资金受限原因；利息与管理员核销有独立事件。

`audit_replay` 按 purpose 推导用户、库存、欠币和锁金变化；原来“用户 treasury 只增手续费”的推导不适用于借币/归还。不得同时把相同现金变化算作贷款流水与 FX 成交两次。读取历史截止点可复算，最新重放与数据库一致；检测直接改本金、锁金、库存、费用或目的的篡改。

`LiquidationAction.kind` 增加 cover_group，迁移同步更新 CHECK；新增实际金支出、归还外币量与 short 后态。现有 `debt_after`、`total_proceeds` 保持金债/卖出回收语义，不用负数塞回补支出。run 起点增加外币与风险基数快照，margin 的历史版本明确，手续费按 gold 或 FX pair 分币种累计，不能把不同货币直接相加。

`AccountValuation`、风险决定及强平事件对未知清算净值使用可空金额和明确的 blocked 原因。涉及 run/事件起点净值的旧非空列须迁移为可空，并保留历史数值；未知值不写成零。进入触发、恢复、组排序之前先分支处理估值完整性，不能对 None 做比例比较，也不能沿用“金债零就 recovered”。

资金入口验收必须逐项覆盖：

| 入口 | 必须遵守的规则 |
| --- | --- |
| 金圆券借还、普通卖出后的自动还债 | 不使用 S；有欠币则完整风险依赖 |
| FX/LMSR 买入与跨市场 writer | 现金用途及交易后共享准入，不靠金债为零绕过 |
| 兑换、弹幕、其他真实扣款 | 任一负债都属于有债；锁金不可消费 |
| 注册、奖励、充值、退款 | 正向资金有来源、审计与经济版本，不吞掉锁金 |
| 管理加减款、强制放贷、批量重置/大赦 | 不写 C<S，不只免金债就声称无债；存量空头需显式处理 |
| pair 暂停、费率、注撤资、关闭归档删除 | 门闩/版本完整；欠币仍存在；清理前非零检查 |
| 排行榜、称号、财富和消费榜 | 统一扣负债，避免用售空所得刷排名或买称号 |
| 赛季重置、备份恢复、利率维护 | 停写、按币种还原/核销与库存对账，不留借币残账 |

## 13. 不可执行债务、回滚与发布

增量迁移创建空头表，追加 pair 借出上限、成交 purpose/请求字段、强平动作字段/约束；不把任何现有钱包负数转成已批准空头，不更改现有现金、金债和授信上限。新开空总闸默认 false、pair 额度零。

上线顺序：完整备份 → 停经济写和调度器 → 迁移 → 部署所有相关写入口与读模型 → 核对旧账 → 保持开空关闭进行回归 → 运营显式配置额度并小规模开空。利率先在启动前确定，既有负债改率须完成旧率维护结息。

存量空头存在时，不能关闭统一风控而回退到只识别 `User.debt` 的模式；启动必须拒绝此组合。开空闸关闭只进入停止增险阶段，回补/估值/定时强平继续处理。

旧镜像不能理解外币义务和锁金。部署/回滚工具切换镜像前必须检查目标能力：有欠币或锁金时禁止回滚到旧写实例。不能仅靠旧实例不认识的新 flag 来保证安全。允许的退路是关新开空后正常清仓，再切旧版本，或经明确审批完整恢复匹配的旧备份；不做固定汇率债务转换。

down migration 在外币本金、利息或锁金非零时拒绝。闭仓历史需要先备份，不能以删表完成欠币归零。赛季重置在既有停写单事务流程中明确清理新表并重新建立库存/现金审计锚点，保留 ID 序列，防止跨季历史串账。

## 14. 验收标准

永久测试以实际账务、边界和并发行为为依据，不固化“当前迁移必须是最新”或源码文本。实现阶段至少证明：

1. 正常开空、追加、部分/完整回补，含两侧费用与利息，实际钱币守恒；零费往返不制造盈利。
2. exact-output 买足欠币、费用向上舍入、末位数量和接近库存边界；q>=F、非有限值和存储溢出不能降低记录的负债。
3. C 已含 S，估值不重复增加；售空所得不能用于还其他金债、兑换、弹幕或再开一份满额仓位。
4. 金债零、欠币正的用户仍受准入、结息和强平；所有资金入口不因旧快路径绕过。
5. 无空头时新旧准入/维持/恢复判断等价；有空头时完整组合共享额度，混合多空不按净敞口抵消。
6. 利息读取与写入同源；追加本金不追收历史利息，旧率维护失败整体回滚，不重复计息。
7. 亏损回补可使用本仓额外锁金；其他仓锁金保留，金额不足不无声借新金债；资金受限强平按实际量记账，剩余欠币不被清零。
8. 未知/暂停的空头 K 不变零、增险阻塞；恢复后 run 能续接。reduce_only 允许回补，即使 underlying side 是 buy。
9. 同 key 请求及崩溃重试只有一次借币、售出、锁金、回补和归还；历史请求身份不与现货混淆。
10. PostgreSQL 并发覆盖开空与现货买入、贷款/还款、消费、利息、系统 tick、费率及状态切换；版本重验完整，不持 User 后补拿 pair。
11. 审计历史与 live 对账一致，篡改任一欠币/库存/锁金字段可检出；榜单、风险 API、管理员与清理均识别外币义务。
12. 迁移保留旧数据；有欠币不能旧镜像写入/降级；开空关闭不会停止存量回补；完整备份恢复与赛季重置有对应证据。

性能验证在相同机器/PG/数据/负载下比较旧基线与新版本，不以拒单率上升换取延迟数字。沿用无新增信用的旧交易 P95/P99 和成功吞吐约 5%相对回归目标；若带索引的外币义务检查超标须优化而非删掉检查。另报告 50/100 用户、多 pair 与 LMSR/系统交易并行的扫描耗时、SQL 次数、门闩等待和单批执行耗时。只有定时扫描时，不宣称事件后即时强平。页面验证遵守项目约定，默认最多截图，不自动点击或填写交互流程。

设计数学核对（不接入永久测试/CI）：20,000 个固定种子的无空头状态，比较新旧准入及维持判定，结果一致；六个共享保证金例子按本稿公式核对；48 个 exact-output 舍入情景使用实际 `quote_buy` 独立核对买足数量、较小一单位输入不够和恒定乘积不减。复算脚本见 [设计数学核对](../../analysis/fx-short-design-math.py)，运行方式为仓库根目录 `backend/venv/bin/python docs/analysis/fx-short-design-math.py`。接近库存上限的纯数学情景可能超出现有储备存储范围，实际实现仍须按第 5 节拒绝溢出成交。

这些证据仅覆盖数学与静态代码关系，不是做空业务测试、压力测试或生产验证。产品代码、正式迁移与实现计划均留待 spec 审阅后进行。

用户审阅重点为：真实借币来源、统一风险基数、同 pair 单方向、锁金与收益基准分离、亏损回补/坏账保留，以及首轮统一上限 10 倍的运营建议。上述规则通过后，再按数学内核、债务/现金、组合风控、交易与强平、审计/读模型和发布边界划分实施任务。
