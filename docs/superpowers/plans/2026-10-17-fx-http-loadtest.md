# FX 百人 HTTP 压测与公共 Wi-Fi 限流调整计划

> **For agentic workers:** 实施时使用 `superpowers:executing-plans` 逐项执行；默认主 agent 执行，不自动委派。当前实现 Tasks 1–3；Task 4 需用户完成服务器部署和凭证准备后执行。

**Goal:** 从开发机经正常 HTTPS 入口模拟同一公网 IP 下 100 名玩家交易 FX，输出分阶段的成功吞吐、请求延迟、错误分类和行情表现。

**Architecture:** 保留现有 FastAPI、PostgreSQL、Nginx 和认证机制。管理员在服务器本机执行 CLI，准备测试账户与短期 JWT；开发机只持测试账户凭证，通过 HTTPS 调用真实接口。限流调整与测试工具分开交付，不新增公开压测接口、认证后门、表或常驻服务。

**Tech Stack:** 现有 Python、SQLModel/SQLAlchemy、PyJWT、httpx 0.28.1、Nginx。保留旧 k6 套件；本轮 FX 驱动复用已安装的 httpx，以同一工具处理普通请求和逐帧 SSE，不安装 k6 扩展。

**Spec:** 本文“范围与授权”“限流方案”“管理员脚本”“负载与指标”为本次设计依据，来源于本轮用户约定；管理员本机脚本和 httpx 驱动路线已经用户授权开始实施。

## 限流方案（已确认方向，实施后由用户部署）

| 请求 | 限流键与额度 | 说明 |
| --- | --- | --- |
| FX 报价、成交及普通玩家写操作 | Bearer token，10 r/s，burst 20，nodelay | 覆盖现货、net、融资、short 和挂单写入，不遗漏嵌套路由；管理接口不进入此桶 |
| 已登录普通查询及 `/auth/me` | Bearer token，20 r/s，burst 40，nodelay | 不与同 Wi-Fi 下其他账户共享额度 |
| 匿名普通请求 | 真实客户端 IP，20 r/s，burst 40，nodelay | 无 Authorization 时必须回退 IP，不能使用空 key 意外免限流 |
| 登录、OAuth callback、refresh | 保留现有限制 | 本轮使用预签发 token；百人同时登录及刷新不在本轮验收结论内 |
| 管理接口 | 保留现有 api_admin 桶 | 管理 token 也不能误入普通玩家规则 |
| 公开市场行情 SSE | 同市场/IP 从 10 改为 200，市场总上限仍为 500 | 共用 limiter，LMSR 同样变为 200；私人账户流保持现有实现 |

只用现有 map/zone/location 结构与现有 limiter 常量，不新增用户额度存储。token 桶按 token 字符串区分，不宣称等价于严格按 user ID 防刷。

先核对 Nginx location 匹配优先级，确保 SSE 不被普通 FX 规则覆盖，仍关闭缓冲并保留长连接超时。真实 IP 沿用现有代理部署；如发现 CDN/代理识别不符，报告具体差异后单独决定，不通过伪造转发头模拟百人。

## 管理员脚本

新增 `backend/scripts/fx_loadtest.py`，只有本机 CLI，无 HTTP 路由。提供 `prepare`、`mint`、`inspect`、`cleanup` 四个子命令；输出本轮 manifest，将用户 ID、市场 ID、run ID 和临时状态记录到私有文件，不加数据库字段。

- `prepare --run-id <id> --users 100 --initial-cash 100000 --output-dir <private-dir>`：在维护窗口、停止经济写入后执行；通过 ORM 创建普通真人类型账户，`casdoor_id=loadtest:<run-id>:<序号>`，`is_superuser=false`、`is_bot=false`。不改已有用户，不调用 Casdoor，不启动第二个应用 owner 或调度器。
- 账户初始余额及审计注册记录遵循现有注册语义；测试账户可在明确测试用途下预置 TOS 接受时间，manifest 记录该事实，不修改正式注册要求。
- 使用专用测试 FX 市场，记录被暂时暂停的原交易市场。当前只允许一个 FX 市场处于交易状态，因此切换在维护窗口执行；测试参数以原市场的池子规模、费率和相关配置为基准，显式记录差异。不得直接借用 ID 8 成交后仅删除账户并声称原市场已还原。
- `mint --run-id <id> --output-dir <private-dir>`：复用 JWT payload/签发规则，仅给该轮普通测试账户签发短期 access token，建议有效期 60 分钟，不发 refresh token，不修改全站 token 有效期。必要时只对这批账户重新签发。
- 凭证文件权限 0600，目录 0700；日志不打印 JWT 或签名密钥。用户将凭证文件放到开发机，告知路径；manifest 可不含 token。
- `inspect --run-id <id>`：只读列出本轮用户、市场、关联表数量和待恢复状态；同 run 重复 prepare 不覆盖现有资金或市场。
- `cleanup --run-id <id> --dry-run` 默认只列清理对象；实际执行需明确该 run ID，且先停止压测和全部经济写入。按当前 FK 顺序事务删除该轮专用市场及账户的依赖记录，覆盖执行回执、成交、钱包、空仓、挂单、行情、清算、账本及审计引用，不复用旧 LMSR 删除 SQL。
- 清理关联按 manifest 中实际 ID 和本轮命名标记交叉核对，不仅靠模糊标题。发现其他账户参与测试市场等超出本轮的依赖时，先报告，不自行扩大删除范围。
- 清理后恢复准备阶段暂停的原市场状态；不覆盖其资产、池子、行情或期间无关配置。不执行 TRUNCATE、全库恢复或自动回滚整个业务库。
- 使用专用市场时，本轮系统事件和机器人是否作用于测试市场必须在开测前核对；记录实际开关，不把未启用的后台混合负载算作已测。若需要另改后台任务或生成一套市场参数，先提交具体选择。

## 负载与指标

建议新增 `loadtest/fx_http.py`，复用现有 httpx + asyncio；不模拟前端 DOM，不新增服务。每个测试账户最多一笔在途成交，独立 token、账户版本和请求编号。

| 阶段 | 负载 | 目的 |
| --- | --- | --- |
| 冒烟 | 1 人，60 秒 | TOS、账户上下文、报价、真实买卖、两类 SSE 首帧均有效 |
| 逐步升压 | 10 → 30 → 100 人，每档 60 秒 | 观察延迟和错误随人数变化 |
| 百人稳态 | 100 人，5 分钟；每人每 5–10 秒完成一次成交循环 | 名义目标约 10–20 次成交/秒；报告实际到达和成功率 |
| 集中下单 | 100 个独立账户在约 2 秒窗口内各提交一笔，随后观察 60 秒 | 看热点排队、尾延迟及恢复 |

以当前 FX 页面真实调用为准，优先使用 `/net/quote`、`/net/trades`、账户 context/version 和行情端点，不能只压旧现货捷径。普通资金交易不跨零、不借款；先买后按真实余额卖，避免大量余额不足请求占据测量。使用真实经济版本和每笔唯一 idempotency key，业务拒绝单独计数，不自动重试掩盖首次失败。

所有稳态在线账户各维持公开 FX SSE 和私人交易 SSE；账户版本检查沿用页面 15 秒节奏并错开起始时间。公开图表初次请求在入场时分散发送，不额外加入页面没有的高频轮询。

输出每阶段 JSON 汇总、每秒进度与请求样本，至少包括：

- 实际请求到达率、完成率、成功成交数/秒；达到的在线账户数、SSE 连接数和超出节奏的延迟，不能只报告目标人数。
- 报价、成交、账户读取各自的 P50/P95/P99；成功与失败延迟分开，保留各阶段，不能混成一个总分。
- 401/403、业务拒绝、版本冲突、429、5xx、连接错误和超时分别统计；解释未成交原因。
- SSE 建连到首个合法帧耗时、断连和重连次数；按关联事件检查成交后可见时间。无法可靠关联的推送只报告接收间隔/事件年龄，不宣称端到端广播耗时；跨机器时间比较标注时钟偏差。
- 不输出 token、Authorization header 或私人账户全量响应。结果保存在 `loadtest/results/<run-id>/`。
- 纯 HTTP 不提供 CPU、内存和数据库锁指标；用户若有现成监控可同步观察，不将安装监控作为前置条件。

开测前以成功 JSON 响应和合法 SSE 帧预检；1 人冒烟必须真实成交成功。运行中 401/403 立即停止；稳态滚动 30 秒内 429/5xx/超时合计超过 5%，或成交 P99 超过 2 秒，则停止增加负载、排空并报告。集中下单阶段单独标记峰值，不把预期排队混入稳态阈值。无自动重试队列或故障恢复流程。
