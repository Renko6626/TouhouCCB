# SSE消息构造复用与writer只读SQL审计

状态：用户于2026-10-18明确要求sol子代理执行SSE审阅优化，并并行只读分析writer风控→买入SQL。保持现有架构，SSE只做数据复用和批量消息构造。

## 目标与边界

- 私人SSE对相同pricing内容复用一次构造和UTF8编码，仍逐订阅者放入原有队列；账户与订单通知也尽可能按一次发布编码一次。
- 公共SSE已有共享bytes，核对后保持，不重复实现。
- 不降频、不合并丢弃事件；保留每连接FIFO、同步首帧、15秒检查、认证/过期/断连、队列容量及满关闭策略，保留公共精确历史游标与FOR SHARE。
- 不改writer、风控、账户版本、资金事务或数据库模型。不能为了本次复用新增队列、恢复流程或缓存失效机制。
- writer审计只写方案，明确同一账户锁后可复用的数据与不能省略的重读/锁；不得改代码。

## 执行

1. SSE sol工作者核对现有共享点，局部实现，相关已有检查与必要行为覆盖，自审提交。
2. 独立sol审阅固定diff；具体问题修正后限定复审，不扩大理论防御需求。
3. 使用相同100用户/200 SSE、初始化与保护阈值，对固定58101e1和最终实现顺序运行一次无profiler性能对照；报告CPU、实际成功吞吐/延迟、读延迟、SSE帧/字节、保护停止和未运行项。无性能收益也如实报告。
4. 检查主工作区修改未变后只应用本轮patch；保留主工作区每IP10限额与无关改动，运行受影响边界检查，保留实验与审阅证据。
5. writer只读报告独立交付，后续实现须根据具体方案另行确认。
