# FX 子游戏 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有预测市场旁实现一个默认关闭、可审计、可恢复的金圆券/幻想外币 FX 子游戏，包含 AMM 成交、宏观事件、管理员控制、玩家页面和净值/赛季集成。

**Architecture:** FX 使用独立 SQLModel 表和 service 层，不复用 LMSR 的 Market/Outcome/Position/Transaction。所有玩家、噪声和宏观干预都通过同一份 AMM 事务服务完成；池子行锁先于用户行锁，幂等键和数据库状态负责并发与重启恢复。公开 API/SSE 只返回白名单行情和新闻字段，隐藏目标价、冲击参数、未来订单和随机状态仅留在服务内部。

**Tech Stack:** Python 3.13, FastAPI, SQLModel/SQLAlchemy, Alembic, Decimal(16,6), APScheduler, Vue 3, TypeScript, Naive UI, ECharts/lightweight-charts, Vitest。

**Spec:** `docs/superpowers/specs/2026-09-28-fx-market-design.md`

## Global Constraints

- FX 总闸默认 `false`；未建立并注资货币对前不得开市。
- 第一版只支持一个处于 `trading` 状态的金圆券 ↔ 外币货币对；不做外币间直兑、杠杆、卖空、限价单、用户做市、真实汇率源或 quant/PvE 接入。
- 所有金额和数量使用现有 `Decimal(16,6)`；手续费向上量化到 6 位，输出向下量化到 6 位；禁止零输出和非正储备。
- `User.is_bot=true` 永远不能调用 FX 成交接口；有 `debt > 0` 的用户不能买入外币，但可以卖出已有外币。
- 玩家交易、系统订单、钱包、池子、储备、审计必须在同一事务中守恒；公开响应不得暴露隐藏目标价或未发布事件参数。
- 已发布事件不可编辑或撤销；调度器重启后以数据库状态恢复，首次干预不得重复执行。
- 不新增依赖；生产部署前总闸保持关闭，不直接修改生产数据库。
- 页面验证按仓库偏好最多截图查看，不自动点击按钮、填写表单或执行浏览器交互流程测试。
- 系统资产守恒必须按币种分别验证：`G + T_G` 和 `F + T_F` 在无手续费系统订单前后相等；系统输入从 treasury 扣除，输出进入 treasury。
- `event.parameter_snapshot["spent"]` 只能累计本事件实际金圆券名义支出；不能使用全局 `daily_spend` 代替。
- 单个 pair/event 失败必须由 savepoint 或独立事务隔离；不得中止其他 pair，不得提交半笔系统订单。
- 任何任务的完成证据必须包含可执行行为测试；helper、源码字符串和恒真 identity assertion 不算验收。

## Review Focus

- 过期报价、并发买卖和同一幂等键重试：只能一次扣款，参数不一致必须拒绝。
- 输入币种手续费、6 位舍入、极小金额和池子安全下限：不能出现负储备、零输出或守恒误差。
- `is_bot`、负债用户、未同意条款、暂停货币对和 FX 总闸：错误码明确且不产生副作用。
- 事件手动发布、计划发布、进程重启和重复扫描：事件与首轮干预只能提交一次，失败可重试且有原因。
- 公开行情/SSE/图表和管理员响应：只能暴露白名单字段，不能泄露目标价、冲击幅度或未来订单。
