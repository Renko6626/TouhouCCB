## Important

1. **暂停处理必须在挂单入口明确拒绝。** 现有 `net_trading.py:153` 和 `shorts.py:857` 仍允许部分暂停状态下减仓，不能假设现有成交函数必然拒绝。主 agent 核对对话：用户已经确认挂单到价后暂停/总闸关闭也失败，故不需重新选择规则；设计应明确这是挂单的执行前检查，不修改网页直接成交规则。
2. **成交事务接缝待具体化及架构确认。** `execute_net_trade` 入口 rollback、末尾 commit（`net_trading.py:278、385`），不能外层锁单后直接调用。最小推荐是提取事务内执行核心，网页包装器维持现有行为，挂单将资金变更和订单成功一起提交。空头回补已有不提交的 `execute_short_cover_in_session`（`shorts.py:775、801`）。不复制结算算法。
3. **动态借款和比例回补必须在锁内真实状态计算。** 买入先回补、释放锁金，再计算新多头预算（`net_trading.py:104–142`）；自动借款应在这一模拟路径计算缺口，不能直接总额减现金。比例空头回补应先结息（`shorts.py:882–893`），100% 使用 `cover_all`；内部金额保护来自锁内报价，不复用过期网页 `max_gold_in`，不增加玩家滑点参数。
4. **写清槽位/撤单/成交锁序。** 沿用 GATES → pair → User，再锁订单校验等待状态，之后资金写入。创建用 User 锁下计数插入；撤单用 User → order，不持这些锁再申请 pair gate。资金回滚后记录失败也要重查订单，避免覆盖撤单。此为局部实现细节。
5. **未知提交处理不能默默扩成恢复系统。** 草案提出无法核对则保留槽位，但未说明扫描如何避开。若新增持久核对状态/恢复流程，应单独提案确认。最小原则是固定订单请求编号、复用现有回执唯一约束、异常先核对，不另起编号重复成交；不能凭理论风险扩大第一版。
6. **市场删除和 reset 要确定最小政策。** 新外键与现有直接删 pair 路径冲突（`admin_fx.py:397、402`）。推荐在“有挂单历史则拒绝删除，改用归档”与“保存币种快照、外键允许置空”中选择。season reset 接入订单清理及 FxExecution 删除顺序（`backend/scripts/season_reset.py:73`）；business reset 现有 head 建库和业务表为空验证可沿用，不新增重置系统。

## Minor
