# FX 报价快照与内存加速计划

本文记录后续优化方向，不改变当前交易和风控实现，也不代表已经启用。

## 当前边界

LMSR 已有每市场 `MarketState`：内存保存量化后的 `q_dec`、派生价格和市场状态；数据库 `Outcome.total_shares` 是提交后的镜像。每个市场由 writer 串行处理，提交后更新内存；更新失败则标记不可用并从数据库重载。

FX 当前没有内存权威成交状态。每次成交在数据库交易对行锁内读取最新的储备、状态、费率和 `pool_version`，重新计算 AMM 报价，再写入钱包、池子、国库和交易记录。这个边界保留了用户交易、管理员注撤资和系统干预之间的统一账务顺序。

## 第一阶段：只读报价快照

优先实现一个按 `fx:{pair_id}` 命名的内存快照，用于报价页、行情展示和重复读取：

- `gold_reserve`、`foreign_reserve`、买卖费率、状态、`reduce_only`、`pool_version`；
- 快照只用于只读报价和展示，不直接作为成交储备；
- 成交、强平、管理员注撤资、系统干预仍在数据库锁内重新读取并报价；
- 提交成功后更新快照；更新失败将该交易对标记为 `unavailable`，释放门闩后从数据库重载；
- `pool_version` 变化使旧快照和风险估值缓存失效；重启时从数据库恢复，不能依赖内存持久化；
- 不同 FX pair 使用独立命名空间，不能与同 ID 的 LMSR 市场共享快照、序列号或限流键。

这一步与 LMSR `MarketState` 的结构相似，但 FX 只把它作为读缓存。报价响应可以使用快照，最终成交报价必须在锁内重算，避免并发成交或撤资造成超卖、余额覆盖或错误授信。

### 更新与失效契约

首期仅在唯一写进程启用缓存；只读实例绕过本地报价缓存，读取数据库，不假设进程间共享内存。无需为此新增消息总线。

所有改变报价输入的入口都必须在同事务推进 `pool_version`，包括用户交易、强平、注撤资、系统成交以及状态、只减仓和费率修改。提交成功后，由提交方主动安装不可变快照或标记失效；回滚不发布快照。版本号只是比较依据，不能自行通知缓存更新。仅修改与报价无关的新闻/隐藏目标时，不要求重建储备快照。

写进程在提交后仍持目标品种独占门闩，先安装新快照再释放；读请求仅短暂持共享门闩取得快照引用，释放后做纯报价计算。快照已失效时读请求回退数据库或返回可重试错误，不能无限使用旧值。安装只接受不小于当前缓存版本的快照；重载应在目标门闩下重新读取，避免旧的异步重载覆盖更新版本。缓存不可用不等同于数据库交易对停牌，不改变已提交的资金交易。

已有清算价值数学缓存与本方案分离：风控仍在门闩内读取权威数据库快照、核对版本后才复用数学结果，绝不直接信任报价展示缓存。任何公共响应仍须经过既有字段白名单，不能把缓存内的储备或运营字段直接序列化给玩家。

## 第二阶段：统计与行情缓存

在确认第一阶段收益后，再缓存每个交易对的分钟成交量、24 小时成交量和最近行情帧。启动时从数据库恢复窗口，运行中按提交后的交易更新；有界队列只负责发布，不参与资金提交。多个 SSE 客户端共享同一个已生成帧，避免每个连接重复聚合。

成交量统计缓存失效或落后时，允许行情短暂显示旧值，但不能影响成交、净值、借款额度或强平。发布器停止、队列满或广播失败都只能丢行情帧，不能回滚已提交资金交易。

## 暂不做：FX 内存权威成交状态

暂不把 FX 储备迁移为类似 LMSR writer 的内存权威状态。FX 有更多写入口：玩家买卖、强平、管理员注撤资、系统噪声/干预和事件操作。若引入 per-pair writer，必须同时解决：

- 所有写入口统一排队，禁止任何旁路直接改储备；
- 数据库提交、内存更新、崩溃恢复和重放的顺序；
- 管理员操作与系统调度的公平性和背压；
- 进程重启时储备、国库、钱包、审计和 `pool_version` 的一致恢复；
- 多 FX 抵押估值在 writer 排队期间的版本复检。

AMM 数学本身很便宜，当前更可能的瓶颈是数据库往返和统计查询。因此只有专项压测证明数据库成交路径是主要瓶颈时，才进入这一阶段。

## 验收门槛

第一阶段必须比较报价读取延迟、成交延迟、数据库查询数、快照命中率和 `pool_version` 冲突率；覆盖普通买卖、强平、注撤资、系统干预、暂停/只减仓、重启恢复和同账户跨产品借款。统一风控仍必须在门闩内使用最新数据库状态，不能用展示缓存代替清算报价。

正确性指标要求：回滚发布次数为零、版本倒退次数为零；在读请求取得共享门闩之前已提交的更新必须可见，或明确回退数据库/报错。并发成交导致用户报价与执行价不同是正常情况，由锁内重报价和滑点限制处理。性能阈值在实施前基线确定；至少保留既有成交路径吞吐下降及 P95/P99 增幅不超过 5% 的约束。统计缓存的恢复查询限定在所需 24 小时窗口、按交易对批量，后台任务和队列有界。
