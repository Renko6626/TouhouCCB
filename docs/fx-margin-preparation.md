## 1. 用户确定的场景与目标

- 50–100 名玩家，每人初始 500 金圆券；总初始本金 25,000–50,000 金圆券。
- 外币名称为「摩拉」，初始汇率为 **1 摩拉 = 0.2 金圆券**。
- 希望支持最高 20 倍杠杆。按全部本金作保证金计算，单人理论名义仓位 10,000 金圆券，全体理论名义仓位 500,000–1,000,000 金圆券；未扣手续费及风险缓冲。
- 下一阶段准备 FX 强平。FX 与 LMSR 应共享适合复用的基础能力，并保留各自产品规则，避免完全割裂或全部耦合。

当前 FX 是现货 AMM，禁止有债务的用户买入；FX MTM 不计入借款额度或强平抵押物。20 倍杠杆及 FX 强平不是当前已有功能，不能只改配置启用。

## 2. AMM 深度测算（已校正）

设金圆券储备为 G，摩拉储备为 F，初价要求 G/F=0.2。忽略舍入，累计净买入 g 金圆券后的边际价格满足：

`P_after / P_before = (1 + g/G)^2`

这里 g 是扣费后实际进入池子的净金圆券，表中假设期间没有卖出、系统干预或注撤资。百分比是成交后的边际价格变化，不是平均成交滑点，也不是完整杠杆压力测试。杠杆产品是否实际向池子投入全部名义金额仍待设计。

| 金圆券池 G | 摩拉池 F | 净买入 10,000 金 | 净买入 100,000 金 | 净买入 1,000,000 金 |
| ---: | ---: | ---: | ---: | ---: |
| 500,000 | 2,500,000 | 4.0400% | 44.0000% | 800.0000% |
| 2,000,000 | 10,000,000 | 1.0025% | 10.2500% | 125.0000% |
| 10,000,000 | 50,000,000 | 0.2001% | 2.0100% | 21.0000% |
| 40,000,000 | 200,000,000 | 0.0500% | 0.5006% | 5.0625% |

更正此前对话：200 万金池承接 10 万净买入的冲击为 **10.25%**，不是 5.06%。

## 3. 候选参数（用于后续模拟，不是上线推荐定案）

| 参数 | 候选值 | 含义 |
| --- | ---: | --- |
| `initial_price` / 初始 `target_price` | 0.2 | 金圆券/摩拉；实际初价同时由 G/F 决定 |
| `target_min` / `target_max` | 0.1 / 0.4 | 隐藏目标价边界，不是池价硬限制 |
| 基础测试池 G / F | 2,000,000 / 10,000,000 | 适合先观察有限仓位；不能据此认定能承受所有人满杠杆 |
| 更深候选池 G / F | 10,000,000 / 50,000,000 | 100 人高杠杆场景的比较方案 |
| 最大集中买入冲击约 5% 的候选池 G / F | 40,000,000 / 200,000,000 | 表中百万金净买入冲击实际约 5.06% |
| `buy_fee_rate` / `sell_fee_rate` | 0.002 / 0.002 | 每侧 0.2%，尚需评估高杠杆交易成本 |
| `fx_hourly_sigma` | 0.001 | 隐藏目标对数价格小时波动率 0.1% |
| `fx_step_max_ratio` | 0.0005 | 隐藏目标每 tick 最大相对变化 0.05% |
| `fx_noise_interval_sec` | 30 | 噪声订单平均间隔秒数 |
| `fx_noise_pool_ratio` | 0.00002 | 噪声目标价格扰动及订单投入池比例上限参数 |
| `fx_system_half_life_sec` | 1200 | 常规干预半衰期 20 分钟 |
| `fx_default_price_move_limit` | 0.0025 | 常规系统干预价格移动及订单规模限制；不是全市场涨跌停 |

按每侧名义本金约 0.2% 估算，20 倍杠杆单侧手续费约占初始保证金 4%，往返约 8%，尚未含滑点、利息和强平费用。不能只看价格波动校准风险。

### 事件、预算与仓位候选

- 单人名义仓位上限：10,000 金；全体上限先比较 500,000 与 1,000,000 金两档。多空开放后须分别定义总敞口与净敞口限额，不能以多空抵消后的净额代替全部风险。
- 分阶段开放 5x → 10x → 20x 是此前建议，不是用户已确认的运营决策。
- 普通事件冲击：2%–5%；黑天鹅：8%–12%；事件窗口：180–300 秒。这些是隐藏目标冲击候选，20 倍场景必须另做跳价/连续强平压力测试。
- 单事件预算候选为 G 的 0.5%–1%：基础池为 10,000–20,000 金，更深池为 50,000–100,000 金，最大池为 200,000–400,000 金。
- `fx_daily_budget` 当前代码默认 100,000 金；本轮不确定新的日预算。必须覆盖噪声、常规干预与事件的共同支出，且不能当作强平保险资金。
- treasury 两币种余额尚未确定。池子深度与系统可用干预资金是两个概念；当前 `fund_pair` 同时增加池子与 treasury，落配置时需核对发行总量与初始储备。

## 4. 强平参数必须重新设计

撤回此前「维持保证金率 5%–7.5%，强平触发率 3%–5%」的直接建议：若按保证金权益/名义仓位定义，20x 初始保证金率仅为 5%，该建议不能形成一致可执行的开仓/维持规则。

本轮只确定 20x 对应 5% 的初始保证金比例；维持保证金率、强平触发条件、费用和穿仓处理均未定案。设计需明确：

1. 现有账户级借贷能否复用，或是否需要 FX 保证金子账；共享现金不等于共享所有抵押品风险。
2. 只做杠杆多头，还是支持空头；借入本金或合约盈亏的资金来源与负债记账方式。
3. 展示 MTM、风控估值和实际可清算价值的区别。不能用 `持仓 × 边际价` 代替大额卖出的 AMM 净回收金额。
4. 开仓手续费、买入自我价格冲击、平仓滑点及费用缓冲；防止用自身订单抬价获得虚假可借额度。
5. 维持阈值、部分强平目标、扫描延迟、暂停时减仓通道、并发锁序、幂等与同事务账务。
6. 新闻跳价、多人集中平仓、池子深度下降、预算耗尽和穿仓场景；保险/坏账由谁承担。

## 5. 架构调查交接

用户要求：FX 和传统 LMSR 尽量优雅协同，既不割裂也不过度耦合。

暂定调查方向：共享现金/账务、审计、权限、幂等和事务约定；各产品保留定价、可清算报价、持仓结构及实际平仓执行。共享风险编排是否有必要，应由现有代码证据和两个产品的真实共性决定，避免提前造大而全的框架。

### 5.1 现有行为与参数口径

- 借款额度为 `max(0, k × (cash - debt + holdings_value) - debt)`，见 `backend/app/services/loan_service.py:220`。k 是债务/权益上限，不是名义仓位/权益。忽略费用与滑点，500 本金、20x 名义仓位对应总仓位 10,000、债务 9,500，即 k=19；设置 k=20 则对应 21x 总资产/权益。本文前面的 20x 测算统一按名义仓位/投入保证金理解。
- 现有强平 margin 定义为 `(cash - debt + LMSR_LCV) / debt`，不是权益/名义仓位，见 `backend/app/services/liquidation_service.py:415`。默认 hard=0.2、emergency=0.05；默认扫描间隔 600 秒，见 `backend/app/services/loan_migrate.py:31`。这些是代码默认值，不是已读取的线上配置。不能直接用于 FX 20x。
- 现有管理 API 限制 `loan_leverage_k <= 10`，见 `backend/app/api/v1/site_config.py:69`。只有选择修改既有借贷产品时才涉及这个上限；FX 采用独立参数并不要求放宽 LMSR 的 k 上限。
- FX 已共用 `User.cash`、`lock_user`、审计设施，但有债禁买；交易锁序是 pair → user → wallet → treasury，见 `backend/app/services/fx/trading.py:127`。现有风控估值和强平执行只覆盖 LMSR；`backend/tests/test_fx_valuation.py:76` 明确断言 FX 展示价值不能改善现有 margin_status。
- LMSR writer 强平逐市场提交，每个市场的卖出与还债在同一事务内完成，最后汇总事件，见 `backend/app/services/liquidation_service.py:370` 和 `backend/app/services/writer_ops.py:708`。它不是整个账户所有市场一次性原子清算。FX 当前依靠池子行锁，不走 LMSR writer。

### 5.2 推荐的边界（待产品决策）

优先考虑「统一现金入口 + FX 保证金子账 + 产品各自执行器」。资金转入/转出子账必须原子记账，明确已占用保证金与可花现金，避免两边重复使用同一笔钱。保留既有 LMSR 行为，按实际共性逐步提取基础能力。

| 层次 | 适合共享 | 应保留产品差异 |
| --- | --- | --- |
| 账户与记账 | 用户身份、现金入口、金额精度、审计/重放约定 | 保证金、债务归属、抵押范围、穿仓承担方 |
| 风控流程 | 预筛 → 锁内复检 → 执行 → 记录结果的流程约定 | 风控估值公式、保证金阈值、扫描/触发频率 |
| 平仓执行 | 结果格式、幂等与事务要求、回款与还债同事务原则 | LMSR cost diff 与 FX AMM、持仓单位、部分平仓、收费规则 |
| 行情与运维 | broker 实现、配置注册、日志与管理入口规范 | 产品频道命名空间、产品参数、暂停/恢复策略 |

另一方案是统一账户级债务和跨产品抵押。它需要同时改借贷估值、借款额度、FX 有债禁买守卫、两类资产的清算编排及锁序，影响范围更大；不能把它描述为简单复用 `User.debt` 即可完成。只有明确希望 LMSR 与 FX 互相提供抵押、承担彼此风险时再优先选择。

复用现有流程不等于照搬实现：600 秒扫描、无成交冷却、HALT 豁免、整数股向上取整、无滑点保护等规则均需针对 FX 重新评估。先定义小接口和事务边界，不在本阶段统一两套定价引擎或强制迁移 FX 到 LMSR writer。

### 5.3 已确认的行情隔离缺口

`backend/app/services/realtime.py:60` 的 broker 以裸 int 作为 topic，FX 发布使用 pair_id（`backend/app/services/fx/market_data.py:118`），订阅也使用 pair_id（`backend/app/api/v1/fx_stream.py:64`）；LMSR 使用 market_id，流转发不会按产品过滤（`backend/app/api/v1/stream.py:229`）。

因此同号 pair 与 market 会共用服务端订阅频道、序号与相关限流资源。前端是否显示错误取决于事件处理方式，但服务端消息隔离已经不成立。不能依赖 fx_enabled=false 保证隔离：FX 订阅接口本身未检查总闸。本轮仅记录，修复应采用产品命名空间或独立 broker 实例，并覆盖同号频道的回归场景。

### 5.4 对 DSH 推论的校正与验收边界

- 有限正输入在精确恒定乘积公式下不会仅因卖出量大而把储备耗尽；极端输入、Decimal 精度及持久化范围需另外验证，不能笼统断言大仓位必然使 quote_sell 报错。
- 零费用、无舍入、无中间订单时，买入后卖回全部所得可逆；不能把同一段曲线的开平仓自我冲击重复当作必然亏损。真实风控仍须按当前池状态计算净清算金额。
- FX 子账不会自动解决负债绕过兑换限制、坏账或跨产品转移资金的问题；这些仍须明确规则。表数和实施成本尚未确定。
- PostgreSQL 并发、压力场景、强平延迟和资金守恒需实施阶段专门验证；本次静态调查不代表这些验证已通过。
