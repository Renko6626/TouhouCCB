## Actual changes and contracts

- `compute_fx_candle_rows(events)` accepts only event projections: `id,pair_id,created_at,kind,pre_gold_reserve,pre_foreign_reserve,post_gold_reserve,post_foreign_reserve,gold_volume`. `event_prices(event)` computes six-place Decimal pre/post marginal prices; initialize uses post for both. The sole aggregation algorithm orders by `(created_at,event.id)`, includes all pre/post extrema, sums event gold volume, adds `n_events` for every source record and `n_trades` only for kind=trade.
- `apply_candle_batch(db,*,pair_id,expected_event_id,through_event_id,rows,history_version,history_ready=None)` atomically writes candles plus `last_event_id`. Flusher queue fields/keyword arguments use event cursor names throughout. Generation rejection, duplicate count/volume protection, uncertain commit retry, frozen in-flight ranges, per-pair discard and row locks are retained. Old `last_trade_id` and candle trade ordering fields are never populated with event IDs.
- Runtime state returns `applied_event_id,durable_event_id,history_version,history_ready`. `drain_public_events(pair_id)` returns bounded event deltas/invalidation. Normal query is projected pool events by pair and ascending event ID, limit at most1000. One catch-up processes at most10 pages, then requeues; startup runs bounded rounds with flush/yield between rounds. Four ring retention windows, five-second reconciliation/flush and512 public buffer limit remain.
- Source readiness checks run once per runtime generation at initialization, not in GET or the normal ready tick path. Native readiness needs earliest event initialize, no legacy zero-event candle rows, no FxTrade missing its event, and no fx_fund/fx_withdraw audit missing its event. Failure marks the runtime as requiring offline rebuild and does not start partial aggregation. Legacy nonzero trade cursor with zero event cursor is also blocked. Missing-state legacy sources and zero-cursor legacy sources stay unready. Unready existing ready flags with zero event checkpoint are not trusted by runtime. Checkpoint/generation replacement permits resync after offline conversion.
- Migration makes obsolete candle trade ordering fields nullable, invalidates old `history_ready`, retains source trades/audits/candles until explicit conversion, and adds nonnegative event count/cursor constraints. Existing downgrade history-loss preflight remains before all DDL. Composite audit index `(ref_table,ref_id,event_type,id)` supports startup source EXISTS and administrator keyset query; SQL plan/performance evidence is still Task6.
- HTTP chart remains a JSON list with original OHLCV fields plus `n_events,n_trades`. Header is `X-FX-Through-Event-ID` and generation remains `X-FX-History-Version`; CORS exposes the event header. Coverage includes events actually represented in the aligned window and the prior-close anchor used to carry prices, never unrelated later out-of-window events. Ring fallback checks committed event coverage before trusting a copied ring prefix. Candle/state joined reads and final generation verification prevent generation mixing.
- Persisted/ring readers, window maxima, incomplete history proofs, raw tail and cache coverage checks use pool events. Projected tail is limited to10001 records to detect exceeding10000 and return503 with Retry-After5; no truncation is labeled complete. Output/fine-source ceiling20000 remains.
- Indexed prior event lookup supplies historical carry. Missing buckets become read-time horizontal rows with volume/n_trades/n_events0; real funding/withdrawal/initialize rows retain n_events>0 despite zero volume. No synthetic rows are stored and no current pair price is invented when no historical anchor exists.
- Both history segment codecs add `events:number[]` alongside `trades:number[]`. Envelope adds `events:[{id,ts,pre_price,post_price,gold_volume,n_trades}]` and `history_tail_through_event_id`. Allowlisting excludes reserves, source kind, audit/admin/player data. Production publisher emits events, not trade-ID deltas. Compatibility `trades` input remains available to the serializer but receives no pool event IDs.
- SSE subscribes before reading a shared-pair-lock committed quote/history prefix. It builds a bounded persisted/ring tail rather than calling catch-up from GET. A not-ready/overlarge tail or unavailable read-only consistency lock emits history_ready=false and history_invalidated=true, without a claimed tail/cursor. Publisher copies event deltas/cursor before awaited quote reads, uses captured quote in envelope mode, and invalidates when snapshot generation differs. Legacy tick-only publication preserves notification price.
- Rolling24h derived full buckets and unflushed event SUM include only genuine trade gold volume; exact partial boundaries and fallback still use FxTrade gold-side SUM. Trade/private APIs retain FxTrade IDs. No new event append hook or economic writer was added.
